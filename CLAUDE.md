# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

DeskRAG — a local-first system that captures desktop activity (screen, audio, mouse/keyboard, accessibility tree) into a searchable multimodal "experience memory," retrievable by text, visual example, or behavioral similarity. TypeScript/Node throughout, strict mode, ESM.

Two packages, two independent installs: **`src/`** is the library (published as `deskrag`, root `package.json`), **`app/`** is **DeskRAGApp**, the Electron desktop client over it (`deskrag-app`, with its own `app/node_modules`). `app/` is intentionally NOT an npm workspace member — that's what lets its Electron-ABI `better-sqlite3` coexist with the library's Node-ABI copy (see invariants). `native/` holds the Swift AX sidecar. Default to working in the library; the app is a consumer of its public barrel.

## Architecture — the load-bearing seams

The two rules below are enforced structurally and are non-negotiable; most bugs come from violating them.

### 1. Dual-store consistency (`src/store/`)
SQLite (`better-sqlite3`, WAL) is the relational **source of truth** + high-volume event firehose; LanceDB owns **all vectors** + scoped ANN. They share app-minted **ULID** string keys and are joined application-side. `DualStore` (`store/store.ts`) is the ONLY place both engines are known — callers never see both. Rules it enforces:
- **Write order: SQLite transaction commits FIRST, then Lance add.** A crash in between leaves a relational row with no vector — detectable and re-embeddable. The reverse creates undetectable orphan vectors. `putRegions` is the template every vector-write follows; all writes serialize through a `Mutex` so the commit→add pair can't interleave.
- **Shared ids:** the SQLite primary key IS the Lance row key, verbatim.
- **Delete order:** gather ids from SQLite → delete Lance by id set → delete SQLite.
- **Reconciliation runs one direction (SQLite is truth):** prune orphan vectors, and return *missing* rows (SQLite row present, blob/text available, vector absent) for a caller-injected re-embed callback — so `store/` never depends on `represent/`.

### 2. Vector namespacing discipline (`src/embed/types.ts`)
Embeddings from different models are NOT comparable. Every vector is namespaced `view:provider:model:dimensions` via `namespaceFor()`, and LanceDB keys **one physical table per namespace** — two models physically cannot land in one similarity search. `dimensions` is part of the namespace, so a truncated model is a distinct space. Always store the raw text/frames/AX so vectors can be regenerated if a provider changes.

### Pipeline (each stage narrows scope; retrieval never widens)
```
capture/  → per-signal producers stamp events on a MONOTONIC clock (t_mono, never wall-clock)
segment/  → event-driven boundaries (focus change, dwell gap, bookmark) → ONE granularity, `action` (level 0)
represent/→ 6 embeddable views per segment/frame/region (below)
retrieve/ → Tier0 pHash · Tier1 segment RRF over text views + behavior + a LEXICAL lane ·
            Tier2 frame ANN (scoped to Tier1 segments) · Tier3 region ANN + AX-label FTS
            (scoped to Tier2 frames; the FTS half runs for TEXT queries and needs no model) ·
            Tier4 optional rerank
            → assemble.ts fuses into ranked frames + `highlights` (region bboxes+labels)
```

**Correlate on `t_mono`** (monotonic offset from a session epoch, `timeline/clock.ts`) — never wall-clock; `started_at` exists only for human display. Segments are detected *after* capture, so frame↔segment association and the denormalized `segment_ids` on frame vectors are set lazily at represent time.

**`FfmpegScreenProducer` emits FOUR outputs from one ffmpeg process, and the sampling branches share ONE decimator.** The graph is `[0:v]split=2[v][s]` — a video branch at full `videoFps` (default 10) for watchable video, and ONE sampling branch `[s]select=…,scale=1280:-2,mpdecimate=…[d]` which then splits three ways into gray rawvideo → dHash, MJPEG → `keyframe` blobs, and `mkvtimestamp_v2` → the frame's **capture time** (fd 4). Decimating **before** that second split is what keeps all three paired by index; they are downstream of one filter, so frame N of each still corresponds.

**A SAMPLE IS TIMED BY WHEN IT WAS CAPTURED, NEVER BY WHEN IT ARRIVED, and arrival time was the bug.** `enqueue()` used to stamp `ctx.clock.now()`, which measured **3.050s late on a real avfoundation device** (~0.8s device start-up plus ~2.2s capture-to-delivery) — that is the ~3.2s every stored keyframe lagged its own `t_mono` by. The tap runs with `-copyts`, so its pts is the DEVICE timestamp, and `ctx.deviceClock` converts it to `t_mono` — **the same clock the events in that recording are on**. Dropping frames still breaks no timestamp mapping, now because the timestamp travels *with* the frame. `test/capture.no-arrival-stamp.test.ts` keeps this from creeping back: a wall-clock read in either ffmpeg producer must carry an inline `arrival-ok:` note saying why, so the exception is argued in the code rather than assumed by a reader. Consequences, each measured:
- **The rate limit is `select`, NOT `fps`.** `vf_fps` picks the last frame before each slot boundary and **relabels it to the slot start** — a constant **−0.400s** against the picture at `fps=1` over a 10fps input, where `select='isnan(prev_selected_t)+gte(t-prev_selected_t\,N)'` measured **0.000s**. It also picks the FIRST frame past the interval, matching `KeyframeBudget` one layer down. The comma inside the expression must stay escaped or the graph silently becomes a different, valid graph.
- **`-fps_mode passthrough` on ALL FOUR outputs**, and the mp4 is the reversal. On the three sampling outputs because `select` does not change frame-rate metadata, so the default CFR mode duplicates frames back up to the input rate — measured, **139 frames where 14 were expected**. On the mp4 because **the rail's axis IS its timeline**: CFR re-timed the video to exactly `videoFps` and compressed it against real time by a measured **1.4%** (7.100s of real time per 7.000s of media), which is what forced the rail to rescale. This needs **ffmpeg 5.1+**; `-vsync` is the older spelling and is rejected because it prints a deprecation line through the producer's error channel on every run.
- **The video's origin is a MEASUREMENT, not a guess.** `video.tMonoStart` is the capture time of the first sampled frame — which IS media 0, because `select` keeps input frame 0. It used to be a pre-spawn `clock.now()`, sitting D ahead of media 0 (measured 0.86–1.5s) and putting every lane that distance from the picture.
- **`ffmpegArgs` overrides must carry the tap.** Without one the producer throws rather than stamping arrival: an override is a caller error, not a degradation.

**The audio anchor is device time too, and it takes a different mechanism.** `FfmpegAudioProducer` used `clock.now()` at the first stdout byte, so the audio pipeline's own latency was baked into every chunk. It now reads ffmpeg's pts and converts it through `ctx.deviceClock`; the byte-count offsets are unchanged, because they were always exact — only the anchor was wrong. Neither obvious mechanism works: **`mkvtimestamp_v2` rejects audio streams outright** ("Output file does not contain any stream"), and `ashowinfo` reports the number only through the LOG, which would mean `-loglevel info` — and stderr goes straight to the user, so every ordinary ffmpeg line would surface as an error. So it is `ametadata=mode=print:file=pipe\\:3` on its own fd, with an `add` first because **print emits nothing for a frame carrying no metadata**, and the colon escaped TWICE (the value is unescaped at the filtergraph level and again at the option level). Verified against a real microphone: first pts 3483322543ms against a monotonic reading of 3483322610ms taken 67ms later. **PCM can outrun the anchor**, so windows are HELD until it arrives rather than dropped or arrival-stamped; audio that never gets one is reported and dropped, because mistimed audio would sit silently on a different clock from every other signal.
- **THE BRIDGE: `ax-dump --clock`, and it is why a session can REFUSE TO START.** avfoundation stamps capture timestamps on `mach_absolute_time` (`CLOCK_UPTIME_RAW`, excluding sleep); Node's clock is `mach_continuous_time`, which includes it — **measured 4.78 days apart** on one machine. Nothing in Node reads the other base (`kern.monotonicclock_usecs` tracks it but sits a constant 125011967.742s away, itself unobtainable), so a permission-free sidecar mode reads it once at `CaptureSession.start()`, paired with one `clock.now()`. `DeviceClock` is the ONLY conversion, `timeline/` never spawns, and the pair is stored in `session_clock`. **`deviceClockSource` is required and the constructor has no default options object**: an optional bridge is the silent second convention this removes, so a session that cannot calibrate refuses — before the session row exists, so a failed start cannot look like a recording that captured nothing.
- **`session_clock`'s ABSENCE is the marker for every older recording.** Those timed frames and audio by arrival, so their lanes sit ~1s from the video and the difference is unrecoverable — the delivery latency of a past session was never stored. `SessionTracksDTO.clockCalibrated` carries it and the rail says so; it is REQUIRED on the DTO so the compiler finds every builder, like `showLabels`. Adding the table was verified rather than assumed: a copy of a real pre-change `app.db` opened with the new code gained it and lost nothing (5 sessions, 109 frames, 673 events, 165 segments, 126 blobs, 133 AX snapshots).
- **CONFIRMED ON A REAL RECORDING (2026-08-08), which is the only place it could be** — lavfi has no device clock, so the synthetic bench cannot test the bridge at all. Against a reference clock: frames land at exactly `0.000 1.000 2.000 …`, the first ON `video.tMonoStart`; the video at media 5.000/12.000 reads within **57ms/24ms** of prediction (one frame interval at 10fps), where the same measurement gave **0.93s/1.03s and growing** before; and seeking to media 4/10/16s puts the playhead at 20.30/50.75/81.20% of the axis, all yielding one `totalSec` of 19.70s against a t_mono span of 19.705s. Re-measure delivery latency with `npm run probe:latency --device`; it moves with load (3.050s and 2.417s on two runs), which is why capture time removes *variance*, not just bias.

One scale, at `imageMaxWidth`, feeds the decimator and both branches: decimating at native resolution and re-scaling for the JPEG would be two scale passes and far more sensitive to a caret. Consequence, disclosed: the gray branch downscales from 1280 rather than native, so `phash` values are not comparable with those of pre-2026-08-06 recordings. The video is a **fragmented** MP4 (`+frag_keyframe+empty_moov+default_base_moof`) so a killed ffmpeg still leaves a playable file — verified by truncating one to 49% and decoding its first fragment. `stop()` therefore awaits ffmpeg's exit (SIGKILL after 5s) before the blob row is written. Playback maps a keyframe onto the video with `(frame.tMono − videoBlob.tMonoStart)/1000` — the markers fall straight out of `t_mono`.

**The avfoundation device index is DISCOVERED, never defaulted** (`capture/producers/avfoundation-devices.ts`). `-i "1"` is an index into a table that is different on every Mac and is ordered **cameras first**, so a built-in camera plus a paired iPhone puts the display at 2 or 3. Recording a camera does not fail cleanly — it fails as `Selected framerate (10.000000) is not supported by the device` followed by `Input/output error`, which reads as a bug in the capture pipeline, and the tempting fix (lower the framerate to something a camera accepts) is the wrong one: **the framerate is fine, the device is wrong.** `resolveScreenInput` parses ffmpeg's real `-list_devices` table and finds `Capture screen N`; `resolveAudioInput` does the same for the mic, where `":0"` moves the moment an interface is plugged in. Three consequences, each load-bearing:
- **There is NO numeric fallback when the probe finds nothing.** `screenInputFor` returns `unavailable` and `start()` returns without spawning *or reserving a blob*. Falling back to `"1"` is exactly how the wrong device got recorded; recording nothing loudly beats recording a camera silently. The `"1"` survives only on the paths where the probe never ran (explicit `input`, `ffmpegArgs`, a non-avfoundation `inputFormat` — i.e. every test's lavfi source).
- **A screen-less table is NEVER cached.** The probe costs ~0.5s so the result is process-lifetime cached, but a table with no display almost always means Screen Recording has not been granted *yet* — TCC hides the `Capture screen` entries until it is — and the next thing the user does is grant it and press Record again in the same process. Caching that reading keeps capture broken until an app restart, with nothing on screen to say why.
- **Audio falls back to a real device, screen does not.** An audio index that names nothing drops to the first listed device with a warning, because an unplugged interface must not cost the whole signal; a missing display is a permission problem and has no equivalent. A probe that fails *entirely* overrides nothing — nothing was learned. Taking the *default* is not a correction and must not warn, or every unconfigured recording logs one.

**The audio default is `:default`, and an INDEX is the bug it fixes.** `":0"` was the default and it is an index into that same per-machine table: measured on a real Mac, index 0 was **"Virtual Desktop Mic" and recorded digital silence at -91 dB for a whole session**, while the built-in mic sat at index 1 (-41 dB on the same phrase) and `:default` read -40 dB. Nothing errors, nothing warns, ffmpeg reports a healthy capture and the WAV blobs have exactly the right byte counts — **the only symptom is an empty transcript**, which reads as "transcription is broken". `:default` is avfoundation's own name for whatever macOS Sound is set to, so it is the answer the user already gave the system; picking a device by *name* would be a heuristic guessing at intent. It appears in no device table, so `resolveAudioInput` must never validate it against one — that would "correct" it back to an index. A persisted `":0"` is migrated (`audioDeviceFor`), which is safe only because it cannot be deliberate: it is exactly the string the old DEFAULTS wrote, and the audio signal shipped *disabled* until the same change that turned it on. **This was invisible to the whole suite and took ten seconds of real recording to find** — see the validation rule below.

**`FfmpegAudioProducer.stop()` awaits ffmpeg's exit, and the tail is why.** Bytes ffmpeg has produced are only delivered while the stdout stream drains, so a stop that signalled and returned dropped whatever was in flight — measured against a stand-in child: **16000 of 32000 bytes**. It also short-circuits when the process has ALREADY exited, because `close` has then fired and `once("close")` would never resolve, burning the full 2s timeout on every such stop. Testing this needs a child that withholds part of its output on a timer: a real ffmpeg reading a finite lavfi source outruns the test, delivers everything before `stop()` is even called, and both implementations then look identical (`test/ffmpeg-audio.test.ts` does both).

**Producers never touch the store, including for files they write themselves.** A producer whose subprocess writes directly to disk calls `ctx.reserveBlob(media, codec)` before spawning and `ctx.commitBlob(blobId, {tMonoStart, tMonoEnd})` after it exits; the session stats the file for its byte length. `reserveBlob` returns `null` without a blob store, and a missing/zero-byte file writes no row — a video that never materialised must not sink the session.

**Environment facts are events, not configuration.** Display topology (`display_change`) and keyboard layout (`keymap_change`) both change mid-session and both fail *silently* when they do — a coordinate attributed to the wrong display, text resolved against the wrong layout. Both are `t_mono`-stamped events resolved at lift time by "latest at-or-before", like every other signal. `ActiveWindowProducer` owns display topology because the re-query signal is a focused window lying outside every known display, and it is the only producer that sees bounds (`CaptureContext` is emit-only, so producers cannot observe each other). `KeymapProducer` polls at 60s instead, because a layout change has no observable side effect in anything recorded — the alternative is a long-running sidecar watching a Darwin notification. `ax-dump` grew two permission-free modes for these (`--displays`, `--keymap`); both exit above the `AXIsProcessTrusted` gate *and* above the AX `--self-test` block, or `--displays --self-test` would be swallowed by it.

**Characters are resolved at lift time, not capture time.** uiohook gives a keycode and modifier booleans, never a character. `ax-dump --keymap` dumps the layout's `UCKeyTranslate` table; `resolveKeys` in `lift.ts` applies it as a pre-pass, so `gestures.ts` stays pure and unchanged. Two halves, and the split matters: **scancode → virtual keycode is layout-independent** (a fixed table identifying physical keys, shared by US and Dvorak alike, validated against a live dump and frozen as a test), while **virtual keycode → character is layout-dependent** and comes from the sidecar. The mapping is needed in both directions — the executor must go char → keycode to replay a substituted slot value — so one keymap serves both.

**The modifier rule: a command consumes nothing.** cmd/ctrl present → the plain-column character (which *names* the key: `⌘S` is the S key, not typed text) and every modifier kept. Otherwise the character resolves and shift/alt are **consumed** into the column choice and stripped. Both halves are load-bearing, because `gestures.ts` reads `char` first and treats any surviving modifier as chord-forming: leaving shift on would lift every capital as the chord `shift+A`, and withholding the character from a command would drop `⌘S` entirely at the no-char branch.

**The keymap excludes command keys.** `UCKeyTranslate` maps Escape to U+001B, the arrows to U+001E/001F and the F-keys to U+0010. Unfiltered, a press of Escape resolves as a character and `groupGestures` coalesces it *into* a text run — an ESC byte inside recorded typing. `\r`/`\n` survive (a newline in a text area is content); Tab does not (it is field navigation, and the 500ms focus poller reports the resulting focus change far too late to split the text run).

**A keyframe is a VISUAL STATE CHANGE, decided by ffmpeg, and the old whole-frame hash could not see one.** `KeyframeGate` compared a 64-bit dHash of a **32×32** grayscale thumbnail, which `dHash` then reduced to 9×8 — a Calculator digit on a 2560×1440 screen is sub-pixel by then. **Measured: one keyframe in sixteen seconds of real Calculator use.** `mpdecimate` replaces it: 8×8 SAD blocks against the last KEPT frame, so it sees a localized change. `select='gt(scene,N)'` and `scdet` cannot — both score a whole-frame average, the exact blindness being fixed. What survives in Node is `KeyframeBudget`, a pure minimum-interval rule that keeps the FIRST frame of a burst; `dHash` still runs on every frame because Tier-0 needs the hash on the row, it just no longer decides which rows exist.
- **`lo` is the load-bearing mpdecimate parameter and ffmpeg's default of 320 is far too low for screen content.** 320 is 5 per pixel, which H.264 ringing clears across most of a frame, so nearly every block counts toward `frac` and the filter keeps everything. `DEFAULT_DECIMATE` is `hi=4096, lo=1280, frac=0.003, max=60`, measured against two real recordings plus three synthetic controls (static 20→1; a 64×64 patch changing → 19/19; an **8×16 caret-sized patch → 1**). On a real 18-frame Calculator recording it yields **13 keyframes against 13–14 distinct states counted by eye off a contact sheet** — checked against what the screen did, not against a target count. `hi` measurably makes no difference at these values (4096/16384/999999 all gave 13), so it is a fast path, not a tuned threshold. Recalibrate with `npm run probe:decimate`, which is read-only.
- **DESKRAG'S OWN RECORDER WINDOW DEFEATS DECIMATION ENTIRELY, and that is measured.** The Record screen's elapsed timer displays **milliseconds** (`00:00:07.803`) in a large high-contrast font, so it changes on every single sampled frame. With the window on screen both real recordings kept **18/18 and 22/22** frames at every parameter set tried, including ffmpeg's defaults; masking just that one box dropped them to 13 and 20. Any keyframe measurement taken with the Recorder visible is meaningless — record with the window closed to the tray (recording continues) or mask the timer, as `scripts/decimate-probe.mjs` notes. This is not the app-specific heuristic `trace/` forbids: nothing special-cases DeskRAG out of a recording, it is a fact about what a millisecond clock does to a change detector.

**AX is captured at boundaries as well as keyframes.** A settled screen produces no keyframes — and settled is exactly when a boundary fires, which is why keyframe-only AX has nothing to offer at the moments that matter most. Keyframe AX serves region proposal (keyed by frame); boundary AX serves node predicates (keyed by `t_mono`). `BoundaryAxTrigger` coalesces and applies a settle delay, because the walk is budgeted at 800ms and a flurry of app switches would queue walks faster than they complete; `CaptureSession` drives it, being the only component that sees every producer's events. Both land in **`ax_snapshot`**, which supersedes `frame_ax` — the repo has **no migration mechanism** (`CREATE TABLE IF NOT EXISTS` on every open), so an existing table's shape can never change; `frame_ax` stays readable for older sessions. It cascades from `session`, not `frame`, since a boundary snapshot has no frame. **An empty AX result still writes a row**, so "captured nothing" stays distinguishable from "never captured" — which is what `reason` exists to measure.

**A keyframe walk is assigned to a frame at REPRESENT time, not at capture time.** The walk starts when a frame *arrives*, and a frame arrives a whole capture latency (~2.2s) after the pixels it shows, so the triggering frame is the wrong one **by construction** — region proposal was fusing a tree from one screen with a picture from another. `CaptureSession` therefore passes no `frameId`, and `associateFrameAx` (`represent/frame-ax.ts` — always-on, pure SQLite, between `Linking frames` and `Regions`) points each walk at the frame nearest its own `t_mono`. The direction is **walk → frame**, so two walks cannot contend for one frame and a frame with no nearby walk stays unlinked rather than borrowing one: it keeps a null `frame_id`, `getFrameAx` returns `[]`, and proposal falls back to hotspots and grid tiling. Expect the first keyframes of a session to land there — no walk has happened yet at their content time. This is `AxCapturer.boundaryTMono`'s bug one layer down, and the join is only meaningful because `frame.tMono` is now capture time; `StoredAxProvider` is unchanged and still reads by frame id.

**`action` cuts at VISUAL STATE CHANGE; inactivity is a different question.** A kept keyframe becomes a `scene_change` boundary (priority 15, below `focus_change`, above `dwell_gap`), and `action` carries an explicit `cutReasons: ["scene_change", "focus_change", "bookmark"]`. `dwell_gap`/`burst_gap` are still computed and still returned in `boundaries` — they simply stop producing segments, because inactivity indicates *intent* rather than a change of state, and they get their own rail lane instead. **Measured on two real recordings: 38 `scene_change` cuts, 6 `focus_change`, 2 `session_start`, and zero `dwell_gap`/`burst_gap`/`window`.**
- **Scene times reach `computeBoundaries` as a SEPARATE parameter, never merged into the event list.** A frame is not input: merging would let a screen changing by itself close a `dwell_gap`, which asserts the exact opposite of what `dwell_gap` means. That keeps `segment/` a leaf — `boundaries.ts` still sees only `SegEvent`, and `Segmenter` is the one place frames are read.
- **`action` no longer subdivides by clock (`subdivide: false`).** A sub-window has no boundary behind it and therefore no keyframe of its own, so a caption attached to one is draped over time nothing distinguishes. Span length is bounded by mpdecimate's `max` heartbeat instead. **One segment now holds exactly one keyframe, which is what makes caption extent exact without anyone computing it.**

**Adaptive mouse sampling:** 12ms while a button is held, 100ms otherwise. `Path` fitting cannot recover a drag curve from 100ms samples, and on a drag the path *is* the payload. Not a global rate increase. The throttle rule lives in `producers/sampling.ts` because `uiohook-napi` is native and the producer cannot be unit-tested, but the rule can.

**The 6 views:** transcript (STT — `FfmpegAudioProducer` captures chunks, `TranscriptRepresenter` + `WhisperCppTranscription` turn them into text; a `FakeTranscription` keeps the tests pure), caption (VLM), digest (templated event text), behavior (12-dim input-dynamics vector, a "builtin" namespace — not a network provider), frame-image, region-image. Tier-1 fuses views with **Reciprocal Rank Fusion**, not score averaging (scales differ).

**A segment's span is NOT the span of the speech inside it, and `transcript_clip` is where that fact lives.** `TranscriptRepresenter` already computed per-utterance offsets from whisper's `-oj` output to slice text per segment, and then discarded them — so the only persisted record of speech was a segment span, and the rail drew a 10s bar for a two-second sentence, repeated across every segment the audio blob touched. Clips keep `blob.tMonoStart + s.startMs` as absolute `t_mono`. The segment-level `segment.transcript` column is unchanged: it is what the Tier-1 `transcript` view embeds, and clips are an additional finer record, never a replacement. A provider that reports no timestamps writes **no clips** rather than a guessed interval spanning the whole blob — and the rail's transcript lane then falls back to segment spans *and says so in `warning`*.

**Region proposal (`represent/regions/`, the PixelRAG edge):** fuse three sources — AX tree (`axFilter`: real labeled bboxes, filtered hard), interaction hotspots (weighted DBSCAN over clicks/dwell — the signal video RAG lacks), and grid tiling — via NMS with a cross-source agreement priority bump, then a budget cut. AX role/label is also written to SQLite FTS5 so regions are text-searchable by UI role.

**FRAME↔SEGMENT LINKS ARE WHAT MAKE TEXT SEARCH RETURN ANYTHING, and must never be gated on a provider.** A text query recalls frames purely by segment membership, so with no `frame_segment` rows it returns ZERO results over a full library — no error, no diagnostic. They were written only inside `FrameRepresenter`/`FramePatchRepresenter`, both gated on an image provider defaulting to `"none"`: measured, **2 of 4 real recordings and 38 of 86 frames were unreachable by any query.** `associateFrames` (`represent/frame-segments.ts`) is pure SQLite and runs as its own always-on stage; both image paths call the same `segmentIdsForFrame` so the window rule cannot drift. **The suite could not see this — every `assemble.test.ts` case built the `Retriever` WITH an image embedder.** Test the DEFAULT configuration; it is the one nobody runs.

### The compositional hierarchy (`src/represent/compose/`) — a FIXED three-level ladder, not a recursion

**`segment/` produces ONE granularity, `action`. Everything above it is composed from what those actions mean together.** `task` used to live in `BASE_GRANULARITIES` as a second, LONGER window over the same event timeline, cut by a subset of the same boundary reasons and labelled by the same VLM caption — which is exactly why the rail drew ACTION, TASK and CAPTION as one signal three times. **A bigger box cannot produce a higher altitude**: `CAPTION_SYSTEM` says "describe what is on screen", so running it over a 30s window yields a longer screenshot description. Levels are ordinary `segment` rows keyed `action` | `level:1` | `level:2` | `session`; `segment_tree` and `segment_summary` are TABLES because `segment`'s shape is frozen.

**THE LADDER IS FIXED AT THREE COMPOSED LEVELS, EACH ASKING ITS OWN QUESTION — replacing an open recursion that asked the same question at every altitude.** The recursion's `COMPOSE_SYSTEM` said "group these into larger ones" whether the children were actions or the third composed level, and measuring it showed why that fails: across five real recordings, fan-out collapsed to **1.6 by level 3** — a level grouping 1.6 things is a chain, not a composition — and **21 of 60** composed parents held exactly one child, **11** of those repeating that child's name verbatim (`Start recording session` stacked over `Start recording session` on the rail). `LEVELS` in `compose/levels.ts` now reads `task` (Task — `TASK_SYSTEM`: "group actions into the smallest run you could name as a verb and an object") then `process` (Process — `PROCESS_SYSTEM`: "group tasks into phases serving one outcome"), and the root gets `NAME_SYSTEM` on its own call. `ComposeContext` carries one semantic field, `kind: "task" | "process" | "session"`, replacing `{ level: number, single?: boolean }` — a number could not express three distinct prompts.

**A LEVEL EXISTS ONLY IF IT ACTUALLY COMPOSED SOMETHING, and a level that fails is SKIPPED — never created-and-hidden.** `levelQualifies` requires at least one node with ≥2 children AND fewer nodes than the level below; failing either means the level above adopts the frontier's children directly, so `session` can point straight at `level:1` nodes, or straight at actions. `level:1` (Task) is not model-only, so a declined or malformed reply falls back to `structuralRanges`, which always halves and therefore always qualifies once there are ≥2 children — **Task fails admission only when a BOOKMARK bars every pair**, so every block holds exactly one child (plus the trivial case of a frontier smaller than 2), never because a model declined to group.

**PROCESS IS MODEL-ONLY, and that is what a default install without a summarizer produces: Action → Task → Session, with no Process level at all.** A phase is a semantic judgment — "setting up" vs "doing the work" — and the structural fallback that serves Task (halving adjacent pairs) is meaningless for Process: without a model it would yield phases by POSITION, not by outcome. So Process has no structural fallback; the tree is never absent, only flatter.

**A NODE THAT WOULD HOLD EXACTLY ONE CHILD IS ELIDED, so the tree stops being level-uniform and a `segment_tree` edge may therefore span two levels.** `LadderChild` is a tagged union (`{kind:"leaf"|"node"}`) for exactly this reason. `getDescendantLeaves` already resolves a leaf to itself and `collapseAncestors` already walks children rather than assuming a fixed depth, so BOTH needed no change for elision — one walks to leaves, the other to children, and neither cares that a node's child might itself have been elided from two levels down. **The ROOT is exempt**: a recording whose whole span is one phase still gets a `session` row over that single child, because the root answers a DIFFERENT question from its child (`NAME_SYSTEM`, not a grouping call) rather than restating it — the one place a single-child node is correct.

**A MODEL-ONLY LEVEL NO LONGER ABANDONS THE WHOLE LEVEL WHEN ONE BLOCK FAILS — a human-ruled deviation from the plan, made after measuring what the plan's own rule threw away.** The plan's code returned `undefined` for the whole level the moment any block could not be composed, which discarded phases it had ALREADY composed from other blocks: measured, a 40-action recording split into sixteen size-1 blocks plus one 24-block, and all twelve phases the model had composed from the 24-block were thrown away because the sixteen singleton blocks failed too. A size-1 block was never even SHOWN to the model, so that was never a model failure. It now emits one singleton group per failed child instead of bailing; elision dissolves every one of them, so **no structural Process node is ever written** — "Process is model-only" still holds exactly, it just no longer costs the blocks that succeeded.

**THE STRUCTURAL FALLBACK IS LOPSIDED EVEN ON PERFECTLY UNIFORM INPUT, so elision fires routinely on the no-model path and a root can legitimately hold a MIX of `level:1` nodes and bare actions.** Measured: six actions with identical coherence at every seam merge leftmost-first into 4 + 1 + 1, and the two singletons are elided straight into whatever is above. This is a second reason `LadderChild` has to be a tagged union — not only because Process may be skipped, but because Task's own structural fallback routinely produces singletons.

**ELISION COMPOUNDS ACROSS HOPS, AND NOTHING BOUNDS HOW FAR — a DESIGN CONSEQUENCE of the ladder, not an implementation defect, and invisible below roughly 100 actions.** Three more recordings arrived on the shipped code, one of them **286 actions** — ten times anything the plan measured. The ladder itself holds up at that scale: single-child composed parents 0, single-child roots 0, mean fan-out `level:1` 6.08 / `level:2` 5.47 across all eight recordings, 77 llm / 9 template summaries, and the 286-action recording's own root reads *"Configuring secure REST API integration with Obsidian using Local REST API with MCP plugin"* over nine real phases. But COVERAGE does not hold up: of its 286 actions, only **144 (50%)** have a `level:1` Task parent; **95 (33%) are direct children of the SESSION ROOT**, elided past both composed levels; another 47 hang directly off a `level:2`; and the root itself holds **112 children** — 95 bare actions, 8 tasks, 9 processes. Traced to its mechanism: every per-node invariant above still holds, nothing is malformed, and elision's local justification ("a lone child could only restate it") is correct at each individual hop — what is new at this scale is that nothing bounds how many hops compound, so an item the model never groups at ANY level is carried up at every level and lands on the root. The single largest contributor is `process`, being model-only: a wholesale-rejected block there falls to `singletonRanges`, which emits one singleton per child for the WHOLE block — up to `DEFAULT_BATCH_CAP` (`agglomerate.ts`, still labelled "a starting point, not a measurement") items elided straight to the root **at once**, i.e. up to 24 per rejected block. `DEFAULT_BATCH_CAP` is therefore now a calibration target specifically for the `process` level, where each rejected block costs the most. Nothing here changes the behavior — this recording is documentation, not a fix, and lowering the cap (or otherwise bounding compounding) is the user's call.

**3 of 5 is BETTER than the design doc predicted** — it expected Process to often fail admission on ~30s recordings and treated that as a finding about the data, not a bug. It qualifies on the three 25–31s recordings and not on the other two (26.1s, 30.0s); the reading for those two stands — a recording this short may genuinely have one phase. The zero-duplication row needs one honest qualification: a broader query (any parent SHARING a summary with a child, not only a parent whose ONLY child does) finds exactly one — a `level:2` "record screen" holding two children, one of them a `level:1` also named "record screen". It genuinely composes two things and merely reuses one child's name; it is not the chain defect this table measures, so the row is correctly zero for what it counts, not for every kind of overlap. Driving the app confirmed the rail shows `SESSION · PROCESS · TASK · ACTION` top to bottom, a recording with no Process shows that lane EMPTY with its reason rather than vanishing, and nothing truncates.

**THE RAIL SEEDS THE COMPOSED LANES ONLY WHEN COMPOSING ACTUALLY RAN, gated on the presence of the `session` root row rather than on any segment existing.** `composeLadder` writes a root on every run where composing executed at all, even a one-action session, so a root's ABSENCE marks a recording indexed before the compose stage and never reindexed — the same way `session_clock`'s absence marks a pre-calibration recording. Seeding on "any segment exists" told such a recording both that the model "declined to group" (an empty Process lane) AND that its tasks "all served one outcome" (a session summary) — mutually contradictory, and both false of a model that never ran. A missing lane, an empty lane and a never-composed recording are three different states, the same distinction the rail already draws with `emptyReason` and `null` in a density lane.

**Edges are STORED, not derived from spans.** A parent's span is exactly its children's union, so interval containment looks sufficient — until a parent with a single child has an identical span and containment cannot say which is which.

**TIER-2 SCOPING EXPANDS A PARENT HIT TO ITS LEAVES, and skipping that returns nothing silently.** Frame vectors denormalize `segment_ids` at represent time, long *before* composing runs, so a composed level can never appear in that field: scoping a parent hit directly matches ZERO frames and returns empty with no error — the same shape as the frame↔segment bug above. `getDescendantLeaves` resolves a leaf to itself, so the path needs no special case, including one elided from a level down. `collapseAncestors` is the other half: a parent and its own children both surviving Tier 1 is the reported defect reproduced in the result list.

**A malformed partition is REJECTED WHOLESALE, never repaired** — neither the ranges nor the names survive, the rule `parseInterventionResponse` sets in `trace/`. What changed after measuring is what is ASKED for, not what is accepted: **the model states CUT POINTS, not ranges.** Asked for `{start, end}` over 24 real steps, `qwen3-vl:4b` returned a genuinely good three-task grouping that ended at index **23** — it dropped the last step, so the covering check discarded all of it. Naming where a run ENDS is the only thing it got wrong and the one thing it never needs to say. Measured: model-named nodes **3 of 31 → 8 of 9**.

**The ROOT gets its own call** (`kind: "session"`, `NAME_SYSTEM`). The final collapse asks the model to split a two-item list, which it answers with two groups every time (3 of 3 trials); two does not shrink, so it is correctly rejected and the session's purpose was a rollup on every run. Naming is a different question from splitting.

**Two Ollama facts, both silent failures.** A THINKING model routes its structured answer into `message.thinking` and leaves `content` EMPTY — even with `think: false` — so reading only `content` disabled the LLM path for every such model with nothing saying why. And thinking ON never returned at all on a 30-step prompt, where `think: false` answered in **1.4s**.

**Stage position is load-bearing, and the ordering now lives in ONE TABLE because a second hand-written copy of it went stale.** Composing runs AFTER Digest/Captions/Transcribing (it reads their text) and BEFORE `Search index` (its summaries are a `segment_fts` view). `reindexSearch` shipped without it, so a rebuild produced an FTS index missing every summary and an existing recording could never gain a hierarchy at all. See the indexing pipeline section below — both callers now select from `INDEX_STAGES`, so there is no second list to keep in step.

**The model is accepted ~94% of the time, and the residual is FINE.** Measured over 32 real calls across 8 blocks from three recordings: 30 accepted. A rejection costs that block its LLM grouping and falls back to the structural path — lopsided even on uniform input, as above — which on the rail today shows up as elided singletons rather than a visible run of `· 1 action ·` rollups, since elision now dissolves every one of them. **Tightening the prompt against that old visible symptom was tried and REVERTED**: it moved 94% → 91%, and the mode itself did not recur in 32 trials. Do not re-add it without a measurement that beats 30/32.

**A ROLLUP COMPOSES FROM THE LEVEL BELOW; A TALLY SEVERS THE CHAIN — still true of every level above Task.** Measured before the fixed ladder existed, under the earlier open recursion: levels 3 and 4 were **100% structural** (7/7, 2/2) — by then a block held two or three children and the model answered "split this" with one group each, which cannot shrink and is correctly rejected, so EVERY root was named from tallies and produced things like "launching electron" for a session about recording, arithmetic and documenting. The effect CASCADES beyond preserving meaning: a rollup carrying real names gives the model at the next level something it can group, so the primary path succeeded more too — that recursion's level:2 went 10 llm/3 template → **14/0**, level:4 0/2 → **2/0**. `rollupText` still keys on a level NUMBER internally (`task` → 1, everything else → 2): **Task keeps the tally**, because its children are actions whose text is a whole VLM caption; **Process and the session root compose from real names**, because by then a group's identity IS its children's names.

**PROMPT TWEAKS AGAINST COMPOSITION QUALITY HAVE TWICE MEASURED AS NOISE — REQUIRE 3+ RUNS.** Two plausible changes were tried and both reverted: forbidding "one run per step" moved acceptance 94% → 91% over 32 calls, and requiring a name to COVER all its children moved child-coverage 21% → 47% on the first run, then 33% → 23% and 29% → 27% on the next two (mean 28% → 32%, i.e. nothing). A single A/B run against `qwen3-vl:4b` is indistinguishable from noise. If composition quality needs to improve, the next lever to try is a LARGER or text-specialized model, not more prompt wording.

**ROOT NAMES DO NOT CONVERGE ACROSS RECORDINGS OF ONE TASK, AND STRING EQUALITY IS WHY IT LOOKS WORSE THAN IT IS.** Four recordings of the same task (Calculator → TextEdit → Electron) produced four distinct roots in every arm of every experiment. But the level-1 names they disagree with each other on — "Start calculator", "calculate numbers", "Add numbers from 1 to 6", "verify arithmetic calculations" — all mean the same thing. `nameRoute` votes by EXACT STRING MATCH, so semantically-identical names count as four separate votes and `nameObservations` reports 1 of 4 when a reader would say 4 of 4. Do not add a consensus threshold on top of that test: it would suppress a perfectly good name. Measuring agreement properly means clustering by embedding, which `graph-view.ts` cannot do without an injected embedder (it is a pure root-tested projection).

**`source` is disclosure, not bookkeeping.** `llm` vs `template` is what stops a structurally-composed hierarchy masquerading as a summarized one: the rail sets a lane `warning`, the Library dims a rollup. Composing **cannot fail the run** — every provider error degrades that block to the structural path, or to nothing at all for a model-only level.

**The digest is a retrieval surface, not a tally.** When `action` stopped subdividing, segments went to **945ms** while `buildDigest` still summarized ~10s windows: over 105 real segments **86% were `1 click.` / `mouse movement.` / `idle segment`** — identical strings embedding to one vector with arbitrary ANN order. It now carries the window title, URL, typed text and the label of what was clicked (86% → 4%). Two orderings hold it up: **Regions runs BEFORE Digest** (the labels come from what that stage wrote), and **focus resolves latest-at-or-before**, since a 945ms segment rarely contains its own `focus_change`.

**Typed text is coalesced at SESSION scope, and `typedRuns` is deliberately NOT `groupGestures`.** Typing IS a visual state change, so per-segment grouping shredded a sentence into `typed "this is"` / `typed "a test"` / `typed "of the"` — the phrase existed in no segment. `groupGestures` cannot serve this: it flushes on ANY non-key event because a replayable `type` action must be contiguous. The grouping POLICY differs by purpose; the decoder (`resolveKeys`) stays shared. A run is carried WHOLE into every segment it overlaps, and **backspace is applied** (scancode 14, beside `SCANCODE_TO_VK`) so a run is what ended up on screen — without it a real recording read `"the mergeemergency braoadcast system"`.

**`DEFAULT_RRF_K` is 5, not the published 60, and reverting it inverts the ranking.** 60 suits RRF's original regime (few systems, top-1000 lists, millions of docs). Here SIX lanes (digest, summary, caption, app_caption, transcript, lexical) run over a corpus starting at a few hundred segments, so the lane-COUNT term spans 6× while RANK over a 100-long list spans 2.6× — a segment ranked ~20th everywhere beats one ranked 1st in two lanes *by construction*. Measured: a typed sentence was #1 in the digest lane AND #1 in the lexical lane, and came **13th** fused. **It was 10 while there were five lanes; adding `summary` widened the count term and it was re-swept** — FOUR real recordings, 183 segments, 53 known-answer queries: mean rank 19.0/25.0/32.6/43.3 and recall@5 58%/28%/15%/6% at k=5/10/20/60, monotonic. Swept four times as the library grew and the margin WIDENS every time — recall@5 at k=5 vs k=10 went 47/33 → 52/27 → 58/28. `Tier1Retriever` also carried its own literal `60` — read the constant, never a literal. **`rrfK` reaches the fusion only as `RetrieverOptions.tier1.rrfK`**; passed at the top level it is silently ignored, which looks exactly like an inert sweep since every k then returns one ranking.

**A COMPOSED LEVEL IS UNDER-RANKED BY CONSTRUCTION, AND NO `k` FIXES IT.** A `level:N`/`session` row has ONLY a summary — no digest, no caption, no app_caption, no transcript — so it participates in ONE dense lane where a leaf participates in three or four, and RRF is a SUM. Measured over 20 composed queries whose own `summary` lane ranked them **#1 every time**: none came first fused, ranks splitting 3,4,4,4,4,5,5,9,11 / 26,29,29,30,32,33,34,34,35,36. One in full — query `"Start calculator"`: the correct `level:1` had `summary#1`, the winning `action` had `digest#25 caption#32 app_caption#1 transcript#13`. So "retrieval at altitude" works less well than the summary view promises: a task is findable but rarely first. Fixing it means participation-normalizing the score (which discards the cross-lane agreement RRF was chosen for) or ranking altitudes separately — both design changes, neither made. Leaf retrieval is unaffected (mean rank 1.40 at k=5).

**Tier 1 has a lexical lane; Tier 3's text half needs no model.** `segment_fts` holds each segment's digest+caption+app_caption+transcript+**summary**, written by ONE always-on stage at the END of indexing so it sees whatever the provider-gated stages actually produced. A composed level carries no digest or caption of its own — the summary IS its text, so without it a task is unreachable by an exact term. It needs no provider, so on a default install it is the only route from a query to an EXACT term — where dense views are weakest. Tier 3 likewise takes an OPTIONAL `imageEmbedder`: its AX-label half is the only per-frame evidence a text query has, and without it every frame sharing a segment scores identically (measured: 11 frames tied to six decimals). Region FTS PRE-filters by frame scope like the ANN half — post-filtering a global top-N returns nothing once the library exceeds the limit. FTS ranks are DENSE and keyed on role+label, so frames showing the same control tie rather than being ordered by bm25's arbitrary tie-break.

**`putSegmentVectors` is a bare `lance.add`.** Re-running a represent stage writes a SECOND vector under one id, and neither is an orphan, so `reconcile()` can never prune it — verified: 8 vectors for 4 segments. Any path that may run twice uses `replaceSegmentVectors`; that is what made re-indexing safe. **The FTS tables have no foreign key**, so `deleteSession` clears `region_fts` and `segment_fts` explicitly or a deleted recording keeps answering searches.

### 3. Trace IR (`src/trace/`) — recorded behavior as a manipulable graph

A `Trace` is one recorded session lifted into a linear chain; a `Graph` accretes from merging traces at equivalent states. Nodes are verified states (a predicate set extracted from the AX tree, filtered to stable attributes), edges are action sequences. **Variation comes from recording a task twice, not from a model inventing it** — two recordings differing only in typed text merge into one edge with two slot samples, which is how slots are discovered rather than declared. A revisited state collapses into a loop.

- **Targets are layered anchors** (`ax → visual → point`), recorded independently at lift time and **never derived from one another** at replay time. Anchors resolve against the AX tree captured *at that moment*, the same rule `StoredAxProvider` enforces at represent time.
- **Paths are normalized to a unit box between their endpoints**, so retargeting is the same projection as verbatim replay — one code path, not two. `Path.curve` is a *chain*: a single cubic misses a half-sine arc by ~3% of its chord. Spans split at the **index** midpoint, never at peak residual or the arc-length midpoint — both make the fit flip under a pure translation of the input, because on a symmetric gesture the two candidate samples are exactly equidistant and floating-point noise alone decides.
- **Predicates are tagged `achievable` or `assertable`.** Achievable ones have a repair path (pathfind to a node where they hold), assertable ones can only gate. Setup is therefore not a separate phase: it is the graph, and mid-replay recovery uses the same mechanism. **`reach` is DENORMALIZED into every stored predicate**, so editing `REACH_BY_KIND` changes nothing about a graph already on disk — it needs a rebuild. Measured the confusing way: `url` was flipped to `achievable`, the code and tests all agreed, and a live plan was still blocked by `url/assertable` read straight out of `trace_node`.
- **Identity is predicate-primary; ambiguity declines to merge.** A redundant node is visible and fixable; a wrong merge is silent corruption.
- **A node's identity is WHAT THE TASK DOES NEXT, not what is on screen** (`trace/identity-set.ts`). `extractPredicates` still decides what a live tree *yields* — `STABLE_ROLES`, `isVolatileLabel` and the 64 cap are unchanged — but a node keeps only: `app`; the elements its **outgoing** edges' anchors target; `ax_focused` when an outgoing edge types; the **incoming** edge's `wait` predicates; and a URL prefix. Everything else is dropped, so no page-vs-chrome heuristic is needed — content the recording never touched is excluded by construction. **Measured on a rebuilt real graph: max predicates per node 34 → 4, mean 2.0, and zero nodes carrying page furniture** (the Chrome nodes that held 18 GitHub PR predicates, which made a live armed run fail boundary verification, now hold two). Both halves of the merge contract hold on real recordings: two recordings of one PR page collapse into a single node (`observations = 2`), while the issues page stays separate on its `url`.
  - **This exists because ONE set was doing TWO opposed jobs.** Merging wants more predicates (discrimination); locating wants fewer (robustness). `DEFAULT_MAX_AX_PREDICATES` went 32 → 64 to stop two GitHub pages merging wrongly, and that same move is what made nodes unlocatable. No cap satisfies both.
  - **Waits come from the INCOMING edge**, filtered by what actually held in the observation. A `wait until app(X)` asserts where an edge *arrives*; reading it from the outgoing edge is the same off-by-one that made boundary snapshots describe the previous application. `newlyTruePredicate` is ranked (`app` → `url` → `ax_focused` → rest) rather than first-wins, or a browser edge's wait would be page furniture and would smuggle it back in.
  - **Lift is three-phase by necessity:** full observed predicates → edges → narrow. `buildNode` runs before any edge exists *and* waits are derived from the full sets, so identity can only be computed last.
- **`ax_exists` is keyed by `identifier` where one exists, else `label`** — one predicate per element. `LAYER_CEILING` ranks `AXIdentifier` at 1.0 against a label's 0.8, yet identity was built from labels alone, so the strongest descriptor never reached it; the failing run's own target (`TextArea` `#First Text View`, no label) contributed nothing.
- **`url` is a predicate** (`trace/url.ts`). For a browser the real application is the SITE: `app=Google Chrome` is too coarse and full page content far too specific. The prefix drops id-like path segments and caps at 3, so two PRs in a repo merge while two repos do not. **`achievable`**, not assertable: `Reach` asks whether some EDGE establishes the predicate, and navigating does. Written `assertable` first, which made every browser node a permanently unreachable goal — `buildPlan` turns an unmet assertable predicate on a remainder node into an unoverridable blocker. Wrong-page replay is still prevented, by verification and locating, which both gate on it. Sourced from `AXURL` on the focused window's `WebArea`, read **during** the walk (Chromium puts it at depth 8–11, so a shallow separate search silently finds nothing) and carried as a `url_change` **event**, because `ax_snapshot` has no column and there is no migration mechanism.
- **A node whose identity is only `app` VERIFIES but never LOCATES** (`isLocatable`). `app` is shared by every node in an application, so it cannot answer "which state is this?" while answering "did I arrive?" perfectly well. **Consequence, measured: without a URL only 3 of 8 nodes were locatable; with one, 9 of 13 are.** Web scope is therefore not only about disambiguation — it is what makes a browser node addressable at all, since a second predicate is what lifts it off the floor. Where nodes remain bare `app` they also over-merge (`observations = 6` on one), which is visible and inert precisely because those nodes cannot be located. `run.ts`'s preference for the `expected` node is what carries a run through them.
- **A boundary node's AX tree must be fetched by its BOUNDARY, not by timing.** `BoundaryAxTrigger` waits out a settle delay before walking, so the snapshot's own `t_mono` is always ~250ms LATER than the boundary it describes — measured at 250–252ms across every stamp. A "latest at-or-before" lookup therefore returns the *previous* state's tree, which paired each node's incoming `app`/`window` predicates with the outgoing app's UI. It measured **54% of nodes incoherent** before the fix and 0% after. `getAxForBoundary` matches exactly via `ax_snapshot_boundary`; `getAxAt` remains the fallback for sessions recorded before stamping existed, and **those graphs cannot be repaired by re-lifting** — the stamp was never captured.
- **Waits come from two paths.** A gap ≥ `dwellGapMs` is cut by `computeBoundaries` into a boundary, so it falls *between* spans and never appears as an intra-span idle gesture — and that is the canonical wait. Only smaller gaps arrive as gestures. A wait whose predicate was already true is dropped with a warning, never emitted as a no-op that looks like a check.
- **`trace/` is a leaf** — pure TS, in the barrel, and it never imports `store/`, `represent/` or `retrieve/`. External data arrives via injected callbacks (`VisualMatcher`, `LiftInput.axAt`) and the minimal local `TraceEvent`/`AnchorRegion` shapes (the same pattern `segment/types.ts` uses for `SegEvent`). Graph *persistence* lives in `store/` (the `trace_*` tables, keyed `(graph_id, id)` because node ids are graph-scoped), which imports the `Graph` type — one direction only. No vector space is registered; visual corroboration reuses existing region/frame vectors by id, so graph writes have no SQLite→Lance ordering hazard.
- **Key events without a resolved `char` emit no text gesture, by design.** `UiohookInputProducer` writes `{ keycode, modifiers }` and `resolveKeys` resolves the character from the session's own `keymap_change` event; a session recorded with no keymap therefore loses ALL typed content silently, which is why the Trace stage reports it in its progress label. A static keycode table would fabricate typed content and hide the gap.
- **`parseInterventionResponse` is a security boundary.** An unknown edge id, an undeclared slot, or synthesis under `allow: "select"` all become `{ abort }` — a model must not widen its own permissions by malforming a reply.

See `docs/superpowers/specs/2026-07-30-experience-trace-ir-design.md`. Capture enrichment shipped (`…-replay-fidelity-capture-design.md`); the executor is below. Only subsystem #4, AI-in-the-loop, is still unbuilt — its wire contract is fixed in the IR spec, its runtime is not.

### 4. The executor (`src/replay/`) — the only code that acts on the world

A `Plan` is produced by resolving a graph against the live AX tree; arming it replays those actions with CGEvents. `replay/` is a leaf like `trace/`, and it spawns a subprocess but loads no native module, so it **is** in the barrel.

- **`execute.ts` depends only on an injected `Actuator`, and `test/replay.barrel.test.ts` asserts that no file in `replay/` except `sidecar.ts` mentions `spawn`/`child_process`.** That guard is the whole safety story: the suite is *structurally* incapable of posting a real event. Never widen it by reaching for a process from a resolver, a planner, or a verifier.
- **`native/ax-exec` is a SEPARATE binary from `ax-dump`, on purpose.** `ax-dump` is read-only and three of its modes are deliberately permission-free (`--displays`, `--keymap`, `--clock`); folding actuation in would mean every AX read is performed by something that can also click. `ax-exec` gates on `AXIsProcessTrusted()` *and* refuses to start without `--plan <id>`, so a bare invocation is inert. `npm run build:ax` builds both.
- **The sidecar is long-lived with a JSON-line protocol**, because AX element handles must stay warm between `locate` and the action using them — re-walking the tree in between is a staleness window in which the UI moves.
- **The anchor ladder's middle is ORDERED BY TRUST, not fixed.** `identifier` is always first and `point` always last, but `label` vs `path` is decided per anchor by `pathCeiling(depth)`, which decays a path's trust from 0.95 and crosses below a label's 0.8 just past depth 5. This is not over-engineering and must not be "simplified" back to a constant: two *fixed* orders were each falsified by recording in one more application. Measured path depths are AppKit 4.0, SwiftUI 7.4, Chromium 11.4 (max 17) — and the apps disagree about label-vs-path *because* their depths differ. SwiftUI also carries **0% labels**, AppKit 67% identifiers against Chromium's 9%; availability is a property of the app's AX implementation, never a ranking criterion.
- **Verification is a SUBSET check, deliberately unlike node identity.** `samePredicateSet` is exact because *merging* needs it; verification asks only "does every predicate this node claims still hold", so extra observed predicates are not violations. Exact equality here would fail on any screen that gained anything since recording.
- **Dry-run is the default and arming is one gate.** `blockers` (unmet `assertable` predicates) can never be overridden — no UI action produces them. Brittleness (an edge whose targets are majority point-only) can be, explicitly.
- **A plan STOPS where resolution stops working, and the rest is disclosed unresolved.** `buildPlan` cuts at the first anchor that carries AX descriptors yet reaches no AX rung — the executor *measuring* that it is describing a state which does not exist yet. A point-only anchor never cuts: it is already at its permanent best. That edge and every later one become `remainder` — action kinds, recorded descriptors, recorded points, explicitly not targets — and the cut is at an EDGE boundary, never mid-edge, because a node boundary is the only place the world can be re-observed. `executeRun` (`replay/run.ts`) then loops observe → locate → plan → **arm** → execute, with `arm` INJECTED so `replay/` still never decides to act. The dry-run promise is unchanged in substance — *nothing is posted from a plan you have not reviewed at exact resolution* — and segmentation costs approvals rather than safety. Measured on a real cross-app graph: 2 segments, cut exactly at the app boundary, and 0 anchors falsely resolving in the wrong application across 9 foreign trials.
- **The recorded app switch is SUPERSEDED by the repair, and the repair goes at the edge's END.** On an edge whose destination app differs, the switch is the edge's **final** action when it is spatial and carries no `ax` layer — 4 of 4 measured, and structural rather than lucky: `computeBoundaries` cuts at the focus change, so the switching action is by construction last, and the switch target sits outside the focused window's tree by definition (which is *why* the Dock click is point-only). Every `wait { until: app(X) }` is dropped too, since `runRepair` polls that predicate itself. Both become visible `SupersededStep`s, never silent omissions. The repair belongs at the END because the `app` predicate is on the DESTINATION node while the edge's own actions run in the SOURCE app — placing it first posts one app's clicks and keystrokes into another, which is what the shipped code did. Suppressing the switch is also what makes cross-app edges armable at all: their AX rate goes 0%/50% → 100%, and below-floor edges 2/4 → 0/4.
- **`locateNode` uses the SUBSET rule, not `trace/identity.ts`'s `matchNode`.** Merging needs exact set equality — a differing set is a different state — but locating asks "which recorded state is still true here?", and a live screen that gained anything would never match exactly. Most predicates wins (subset matching is monotone, so a node carrying only `app` is satisfied by every observation in that app), a tie declines, and a **zero-predicate node is never a candidate** — an empty set is vacuously a subset of every observation, so it would verify against any desktop at all.
- **Execution verifies at every node boundary**, using the same subset rule, and a violation aborts naming the predicate. The spec promised this from the start and the code did not do it until progressive resolution needed it, because the next segment re-plans from wherever execution actually left the world.
- **An unmet `app` predicate is repaired by ACTIVATING the app, and the repair is a visible plan step.** `app` is tagged `achievable`, so the IR promises a repair path. The graph does contain the recorded switch — as a point-only Dock click — but replaying a coordinate on a surface whose contents move fails silently, because a click always "succeeds". **Planning may call `runningApps()` but never `activate()`**: activating to discover whether an app is running would change the world the plan describes, and `test/replay.barrel.test.ts` asserts `plan.ts` never calls it. Not running is a blocker unless the caller passes `allowLaunch`, and the decision is recorded on `RepairStep.launch` so the review shows whether a launch can happen. Activation is confirmed by polling the predicate, never by sleeping. Launch resolves by **bundle identifier only** — an `app` predicate carries a `localizedName`, so launching usually reports `not-running`; guessing an app from a display name could launch the wrong one.
- **`type` has no fallback layout.** No keymap, or text the layout cannot produce, is a *blocker* — never a US-QWERTY guess. Same rule, opposite direction, as `resolveKeys` at lift time; one keymap serves both.
- **Clicks are CGEvent, never `AXPress`.** `AXPress` is a different action (no hover, no mouse-down, different event stream), so it would silently diverge from what was recorded.

See `docs/superpowers/specs/2026-07-31-executor-design.md` and `…-2026-08-01-progressive-anchor-resolution-design.md`. **The loop first ran end to end with a real CGEvent on 2026-07-31** — one click, one app, target already frontmost. **On 2026-08-01 a cross-app plan was armed from the app's then-Replay screen and posted real events**: a `3× click` resolved at `identifier@1.00`, a `cmd+a` chord, a `type`, and an activation repair that brought Chrome forward — the first live exercise of chords, typing, the repair, supersession, and a cut plan. It confirmed two orderings that were previously only argued: the repair must be the edge's **last** step (steps 2–5 posted into TextEdit, Chrome was activated at step 8), and suppressing the recorded switch is what makes the edge armable at all (3 of 8 steps superseded, all of them the switch). That run **stopped after segment 1**, failing boundary verification on the 18 GitHub predicates — which is what task-derived identity above exists to fix. **On 2026-08-02, after that fix, a multi-step armed run posted nine steps into a real desktop and was verified on screen**: the reviewer hid, TextEdit came forward, a `CheckBox "bold"` click at `path@0.88` toggled bold, a `TextArea` click at `identifier@1.00` focused it, a `type` put real characters in the document, and an activation repair brought another app forward. That is the first live confirmation of **typing** end to end — keymap captured at record, resolved at lift, replayed through `strokesFor`, characters on screen — and of the focus handoff under a **multi-step** sequence rather than one click.

It then **correctly refused to continue**: boundary verification named `ax_exists(label="Stop recording")`, a button that exists only *while recording*, so the state genuinely did not hold. **DeskRAG is deliberately NOT special-cased out of recordings** — excluding one app by name would be exactly the app-specific heuristic this design exists to avoid, and that predicate is correct identity, unverifiable outside recording mode for the same reason a node recorded with a modal open is unverifiable with it closed. Sessions start and end in the app, so its nodes are hubs paths route through; the remedy is recording a route that does not detour through it, not code. **Continuation past a cut still has never run against a real desktop** (it aborts before segment 2); it runs in the suite via `test/run.expected.test.ts`. Drags remain fake-only. Treat every other figure as a capture-time or dry-run measurement.

**`scripts/replay-probe.mjs` is the read-only harness for all of this.** It wraps the `Actuator` in a proxy that throws on `activate`/`moveTo`/`click`/`dragPath`/`scroll`/`key`, so it is structurally incapable of posting an event — the same principle as the barrel guard, and what makes it safe against a live desktop. Modes: `--offline` (graph only, no permissions), `--sweep` (does any anchor falsely resolve in the wrong app?), `--diagnose-frontmost` (long-lived vs fresh sidecar), `--wait-for <app>` (poll until an app is frontmost, since running the probe necessarily focuses a terminal).

**AS OF 2026-08-06 THE EXECUTOR HAS NO UI AND IS REACHED ONLY FROM THE SUITE AND THIS PROBE.** Everything above still describes `src/replay/` accurately and every `test/replay.*` case is green; what was removed is the app's plan-review surface, which never became reliable — see `docs/superpowers/specs/2026-08-06-flows-graph-exploration-design.md`. The app's screen is now **Flows**, a reader over the same graph. Consequence worth stating plainly: **DeskRAGApp no longer spawns `ax-exec` at any point**, so the live measurements above cannot be reproduced from the app. Re-wiring it is a deliberate act, not a refactor.

### Providers, adapters, and the "not in the barrel" rule
**Every provider is local — there are no cloud adapters and no API keys anywhere in this repo.** Adapters either talk to a daemon on localhost (Ollama), run the model in-process (ONNX), or spawn a subprocess (whisper.cpp, ffmpeg, the Swift AX sidecar). A network call to a third party is a regression, not a feature to add. Anything that embeds/captions/reads-AX is still behind an interface with swappable adapters and a **deterministic fake** for tests — that seam is what makes the suite offline and deterministic, and it stays open even where only one local implementation exists.

Adapters that **load a native npm module** (`onnxruntime-node`, `uiohook-napi`, `active-win`, `sharp`) are **deliberately NOT re-exported from `src/index.ts`** — import them from their own path — so importing the package never force-loads native code. The line is **native module, not subprocess**. Everything that merely spawns a binary is exported and always has been — the Swift sidecar sources (`SwiftAxSource`, `SwiftDisplaySource`, `SwiftKeymapSource`) and the ffmpeg producers alike — because importing them loads nothing until they run. The whole visual/native chain is real and tested; only query vectors are faked (a fake embedder maps identical input → identical vector, which lets tests place exact-match items deterministically).

**THERE ARE NOW TWO LATE-INTERACTION PROVIDERS, AND THEY SHARE THE TILER BUT NOT THE TOKENIZER OR THE CONFIG READER.** `colmodernvbert` (Qdrant's upstream ONNX of ModernVBERT/colmodernvbert, MIT) sits beside `colsmol` in the `ImageProvider` union. `geometry.ts` and `colsmol-tiler.ts` are reused **verbatim**, which is a fact about the models rather than a convenience: the two `preprocessor_config.json` files agree on every field `TileConfig` reads (Idefics3, 2048/512, patch 16, shuffle 4, mean/std 0.5, 64 tokens per tile), so the **≥2048px capture rule applies to both identically** — `SettingsScreen` therefore keys its width and AX banners on a `lateInteraction` flag, never on `"colsmol"`. Three things do NOT transfer, each measured rather than assumed:
- **The ONNX contract is THREE inputs, not four** — no `pixel_attention_mask`, because Qdrant's wrapper builds `input_ids` from the actual patch count instead of masking a padded batch. That is also why it needs no re-trace at a fixed tile count, so there is no counterpart to `scripts/export-colsmol.py`.
- **The tokenizer wraps every encode in `[CLS]` … `[SEP]`** (ModernBERT, not SmolLM2), `<|begin_of_text|>` is NOT in its vocab (ten BPE tokens, not one), and the last grid row's `"\n"` abuts the global block's leading `"\n"` so BPE merges them into ONE token — 884 tokens for a 1280x800 frame, not 885. A query's ten buffer tokens go INSIDE the wrapper, because fastembed augments the query STRING and then encodes. `test/onnx.smoke.test.ts` re-encodes fastembed's exact string and compares it to `buildImagePrompt` element by element; that is the check that pins every constant, not the per-token one.
- **`readTileConfig` is its OWN function, not ColSmol's**: this config puts `pixel_shuffle_factor` at the TOP level where ColSmol nests it under `text_config`. Reusing ColSmol's reader falls through to `DEFAULT_TILE_CONFIG` — also 4, so it would be **right by luck** and would silently stop being right the moment either export changed its geometry.

Two shared helpers keep the local adapters from duplicating each other, and new adapters should use them rather than re-rolling: `src/embed/onnx/tokenizer.ts` (`loadTokenizer` / `defaultConfigPath` — the `@huggingface/tokenizers` load that text, ColSmol and the reranker all need, minus the encode shape, which is the part that genuinely differs) and `src/embed/ollama-client.ts` (`resolveOllamaHost` / `postJson` / `listModels`). The Ollama client deliberately does **not** own failure policy: `OllamaTextEmbedding.embed` throws (a missing vector must not look like a clean write) while `OllamaCaptionProvider.caption` returns `""` (a missing caption is recoverable by reconciliation). `listModels` sources from `/api/tags`, never a hardcoded list — Ollama's *library* now includes cloud-hosted models, and offering one in a "local" picker would route screenshots off the machine. That is a structural guard, not a style choice.

### The desktop app (`app/`) — one more seam: the process boundary
electron-vite + React + TS. Three source roots with a hard rule between them: **`src/main` is the only process that may touch the library, the store, or native modules.** `src/preload` is a typed `contextBridge` exposing `window.deskrag`; `src/renderer` sees only plain serializable DTOs.

- **`src/shared/types.ts` is the contract** — DTOs (`FrameHitDTO`, `ResultDetailDTO`, `SettingsView`, …) plus the `IPC` channel-name map, so main and preload can't drift. It imports nothing from Node or `deskrag`; both sides depend on it. Changing an IPC shape means changing it here first.
- **`DeskRagService` (`main/deskrag-service.ts`) is the single owner of the library** — opens the `DualStore` + `BlobStore` under the app data dir, builds providers from settings, runs the record lifecycle, auto-indexes (segment → represent) on stop with per-stage progress events, and hydrates search hits into DTOs.
- **THE INDEXING PIPELINE IS A TABLE, NOT A `push()` ORDER, because the order IS the interface and a second hand-written copy of it went stale.** `index-plan.ts` declares every stage's id, label, `gate`, `needs` and `reindex` scope; `planStages(facts)` returns the ordered selection as a VALUE, so the ordering is assertable in the ROOT suite with no store, no Electron and no model. `index-run.ts` holds the bodies as a `Record<StageId, StageRun>` — the compiler finds a stage that was declared and never implemented, the same device as `showLabels` on `TrackLaneDTO` — plus `runStages`, which takes its runner map as a parameter so the driver is testable without a store. Both modules import no `electron`, which is the condition for a root test to reach an `app/src/main` module at all.
  - **The array IS the order; `needs` is CHECKED, never obeyed.** A topological sort of this DAG is not unique, so its tiebreak would have to be table order anyway. `needs` states the reason each stage sits where it does and `stageOrderViolations` turns what used to be a prose comment into something a test fails on. A dependency absent from a plan is not a violation — gated stages drop out on a default install, and composing still has to follow whatever text stages actually ran.
  - **`runStages` OWNS the progress axis, because the two callers count different things** — the record path counts stages, a re-index counts recordings with the stage folded into the label. Both reporters set `this.downloading`, so a weight download inside a stage rewrites its label; the old rebuild never set it, and now actually runs transcription. `ctx.report(label)` also fixed a silent bug: `run` used to return `Promise<unknown>` and the driver DISCARDED it, so Composing's `— N levels, N nodes` line was computed on every run and emitted on none. Trace only worked because it reached for the service's emitter from inside its own closure.
  - **`tolerateFailure` is data on the spec, not a hand-rolled try/catch**, and it is set on `transcribe` alone — the only stage that downloads on the indexing path, with Trace running after it.
- **RE-INDEX MEANS RE-INDEX: purge everything derived, then run the whole plan.** `reindexAll` is NOT a subset of the record path — being one is exactly how it went stale. Per recording, oldest first: `store.purgeDerived(id)` then `runStages(reindexPlan(facts).perSession, …)`, then ONE `rebuildGraph` at the end. Re-segmenting is safe now and was not before: the old worry was new segment ids orphaning captions and transcripts, and the purge removes those first. `trace` is the one `library-finisher` — a graph accretes, so re-lifting a session into a graph that still contains it double-counts its `observations`.
  - **The purge is what makes a second pass safe, and three write paths are why.** `putRegions`, `putSegmentVectors` and `putFrameVectors` are all bare inserts/adds — `putRegions` even mints a fresh `ulid()` per region — so a second pass over live rows APPENDS a whole second set, and duplicate vectors that still have SQLite rows are not orphans, so `reconcile()` can never prune them. (`putFramePatches` already deletes-then-adds.) **Measured on a copy of a real 13-recording store, re-indexed TWICE end to end: every derived count identical, and every vector table exactly 1×** — `region` 7611 rows against `region_image` **7611 vectors**, 546 frames against `frame_image` **546**, 683 action segments against `digest` **683** and `behavior` **683**, 63 summary rows against `summary` **63**. Without the purge the region table alone would read 15222. Both image-path runs took ~10 minutes over 546 frames with Nomic Vision, which is the other thing to know before pressing the button.
  - **It rebuilds with the providers configured NOW, and that is destructive.** Same store, re-indexed with no captioner/whisper/image provider: `segment_app_caption` 454 → 0, `transcript_clip` 54 → 0, and the caption/app_caption/frame_image/region_image/transcript vector tables all → 0. Recomputable from blobs still on disk, but only by a run that has the provider — which is why Settings confirms first and names which of the three will not come back. Captured rows are untouched (`session`/`event`/`blob`/`frame`/`ax_snapshot` all identical), and leaf actions came back at exactly 683 either way: segmentation is deterministic, only the composed levels differ (96 summaries → 63, Process being model-only).
  - **`CAPTURED_TABLES` / `DERIVED_SESSION_TABLES` / `DERIVED_LIBRARY_TABLES` in `schema.ts` are a GUARD, not documentation.** A root test reads `sqlite_master` and fails if any table is in none of them, so adding one forces a decision about whether a re-index must clear it — an unlisted table is precisely how a purge comes to leave something behind, and nothing else would notice. `transcript_clip` is the one that does not cascade (its FK is to `session`, not `segment`) and must be deleted by name.
  - **A registered namespace whose Lance table is NOT ON DISK must be a no-op to delete, not an error.** Measured on the real store: 12 rows in `vector_space` against 11 directories in `lance/`, because selecting a provider registers the space and the table only materializes on first write. `deleteByIds` opened it and threw `Table '…' was not found`, which took down the whole re-index — and took `deleteSession` down the same way, since both walk EVERY registered space rather than only the ones a session has vectors in. Fixed in the Lance layer, where "delete from a table that was never created" has already achieved its goal.
- **Everything optional is gated, never assumed.** Stage gates read `StageFacts` (booleans only, so `planStages` stays pure): frame/region need an image embedder, captions a captioner, transcripts BOTH audio in the recording and a whisper *binary* on the machine — see below; native producers (`uiohook-napi`, `active-win`, `sharp`) are `await import()`ed with `/* @vite-ignore */` inside try/catch so a missing module disables one signal instead of failing startup. `capabilities()` mirrors this to the renderer for UI gating.
- **An EMPTY whisper setting means "default", never "off"** (`main/whisper.ts`). `modelPath: ""` → the managed GGML (`MODELS.whisper`, `ggml-base.en-q5_1.bin`, 57MB, downloaded on first transcribe like every other weight); `binaryPath: ""` → `whisper-cli` on PATH. The version that read `""` as "no whisper" is what made transcription unreachable for everyone: clearing the Settings field skipped the transcribe stage, and since **only that stage fetches the model**, the automatic download never ran either — presenting as "the download is broken" when the real state was "transcription is disabled". `load()` normalizes a blank binary back to the default; `set()` deliberately does **not**, because it runs on every keystroke and snapping a cleared box back mid-edit would fight the typist — resolution happens at spawn time instead.
  - **Availability is `EnvInfo.whisperConfigured`, never a capability.** `Capabilities` reports configured *intent*, and since no whisper setting can express "off", a `transcript` member could only ever be `true`. It was removed rather than left as a constant. What can still be missing is the binary, which is a fact about the machine — probed with `which`/`existsSync`, and re-probable from Settings because installing it mid-session otherwise changes nothing the app notices.
  - **Transcribing is the ONE stage allowed to fail without failing the run.** It is the only stage that downloads on the indexing path, and it runs **before Trace** — so a network failure, a checksum mismatch, or a binary that vanished after the probe would abort indexing and take the trace graph with it. A session with no transcript is still a session; a session with no graph is one the executor cannot use. `ModelFilesMissingError` gets its own message: a set "Model directory" disables managed downloads *by design*, so the GGML must be placed there by hand — reaching around the override would break the only promise that setting makes.
  - **A weight download rewrites the running stage's label.** `ModelDownloadProgress` has its own IPC channel because a download can start from search, but the indexing screen renders `IndexingProgress` — so 57MB fetched inside Transcribing was a silent stall indistinguishable from a hang. The stage folds it in (`Transcribing — downloading model 23/60MB`), the same way Frame patches folds in its per-frame count. No new IPC.
- **`ensureToolPath()` runs before anything can spawn** (`main/tool-path.ts`, called at module scope in `index.ts`). A packaged macOS app is launched by launchd, not a shell, so it inherits `/usr/bin:/bin:/usr/sbin:/sbin` with **no Homebrew** — and every capture/transcribe subprocess is looked up by bare name. `ffmpeg` and `whisper-cli` therefore appear uninstalled in a packaged build while working fine in a terminal-launched dev run, which is the single most confusing failure mode here. Inherited entries stay first, so a user PATH still wins.
- **The mic entitlements are INERT on an unsigned build.** `hardenedRuntime: true` + `entitlementsInherit` (`build/entitlements.mac.plist`) are what let the bundle's microphone grant reach the *child* ffmpeg that actually reads the device, and `NSMicrophoneUsageDescription` is what makes macOS show the prompt at all — but entitlements only take effect when the app is signed. Without a signing identity electron-builder skips signing and the packaged app cannot record audio no matter what the plist says. Verify with `codesign -d --entitlements - <app>`, not by reading the yml.
- **The mic is requested at Record, not at launch.** ffmpeg reads the device in a child process, and an ungranted device fails with a bare avfoundation `Input/output error` that looks like a broken build. `startRecording` requests first, so the system dialog appears at the moment it makes sense, and a refusal **drops the audio signal** rather than pretending to record it.
- **Bytes don't go over IPC.** Keyframes are served by blob id through the privileged `deskrag://frame/<blobId>` protocol (`main/protocol.ts`), registered *before* `app.whenReady`.
- **`SettingsStore` holds no secrets** — every provider is local, so there is no key, no `safeStorage`, and no `keys.enc`. It deletes a stale `keys.enc` on open rather than leaving unreadable ciphertext on disk. A persisted provider value outside its allowed set (`PROVIDER_VALUES`) resets to the default instead of being carried forward, so settings can never name a provider the app cannot construct.
- **Data dir:** `<userData>/DeskRAG/` (dev: `~/Library/Application Support/deskrag-app/DeskRAG/`) — `app.db`, `lance/`, `blobs/`, `models/`, `settings.json`. `DualStore.listSessions()` is the authoritative session list (SQLite, with per-session counts + the `screen` video blob id), so the Library list can't drift from what delete actually removed. There is no `sessions.json` sidecar — an old one left on disk is ignored.
- **Trace indexing is the last stage, and `main/trace-index.ts` is the only place `trace/` meets the store.** `liftTrace` takes its world through injected callbacks precisely so `src/trace/` stays a leaf; that module binds them. All three environment callbacks resolve **latest at-or-before the `t_mono`** from the session's own event stream, which is why topology and layout are recorded as events at all. It runs after Regions (`regionsAt` reads what that stage wrote) and after Segmenting (boundaries define the nodes). Every session merges into **one graph** (`DEFAULT_GRAPH_ID`), which is what makes a second recording of a task branch or fill a slot instead of starting a disconnected chain — `mergeTrace` seeds a new graph's id from the session, so the id is pinned on write.
- **`KeymapProducer` is wired to the input signal, not its own toggle.** Without it nothing emits a layout, `resolveKeys` has nothing to apply, and every text gesture is dropped — so a recording with keys but no keymap silently loses all typed content. The Trace stage says so in its progress label rather than only in the console, because nothing else would tell the user.
- **Deleting a recording is two calls, in order:** `store.deleteSession(id)` then `blobs.removeSession(id)`. The store records where blobs are; it does not own the files. Rows first — a row pointing at a deleted file is a broken read, whereas a file with no row is just reclaimable disk.
- **Video is served over a separate protocol host.** `deskrag://frame/<blobId>` buffers a keyframe whole; `deskrag://media/<blobId>` streams with `Range` → `206`. Chromium will not let a `<video>` seek without the 206 + `content-range` path.
- **The Library player (`renderer/src/screens/SessionPlayer.tsx`) puts the index on the timeline.** Keyframes become Vidstack *chapter cues* (so the scrubber is divided at exactly the frames that were indexed) and *thumbnail images* (an object array of `deskrag://frame/` URLs — never a WebVTT sprite, which would need a fetch the CSP does not allow). Duration is seeded from the `t_mono` span because a fragmented MP4 reports `Infinity` until buffered, then adopts the provider's value. Playback has no audio — the screen video is video-only — so mute/volume/audio-gain are removed, not styled. That adopted duration is also what the track rail's playhead divides by; see the rail's `videoSec` below, because it is NOT the same number the lanes are measured against.
  - **THERE IS ONE RUNNING CLOCK AND IT IS THE RAIL'S.** The bar's
    `currentTime`/`timeDivider`/`endTime` slots are null. They read MEDIA
    seconds while every lane reads LANE seconds and the two genuinely differ —
    measured, a bar reading `0:29` sat 260px from a header reading

The deduped `labelNode` sequence gave **5 routes, one of them ×5** — the right granularity because a label is app plus its distinguishing hint, which is the level at which a person says "I do this a lot". A predicate-less node is dropped from the key (vacuously true of every desktop, so it names no place); leaving it in put a meaningless `n0 — no state` at the head of all nine routes.
  - **A route is NEVER a graph traversal.** A merged graph composes paths no single recording walked, so enumerating them would present routes the user has never performed as their common flows. A graph with no provenance yields **zero** routes and the screen says why — which is also why the rebuild banner is not optional: every existing install's graph has no sources until `Rebuild trace graph` is pressed.
  - Loosening the key costs precision of highlight, and that is disclosed rather than hidden: several paths can share a route, so `nodeIds`/`edgeIds` are the **union** of what its recordings walked.
  - **A wire's hit path uses `pointer-events: stroke`, never `fill`.** A 2px path cannot be hit with a mouse, so each wire is drawn twice with a fat transparent one beneath — and a filled hit area would make the region *enclosed* by a back edge's bow clickable, which is most of the canvas.
  - **The app filter DIMS, never hides.** Layout is computed from the whole graph, so a hidden node's space stays reserved and its wires end in mid-air.
  - **Selecting a route FRAMES it (zoom included), and the canvas re-fits on resize.** Centring on the route's first node keeps the fitted zoom, which on the real graph — nine nodes in one rank — pushed all but two cards out of the viewport: measured in the running app, the route lit up correctly and could not be seen. Re-fitting on resize is newly SAFE because the 2s location poll that forced fit-once is gone with the executor; without it, opening the drawer (~40% of the height) leaves the cards running under the zoom controls. A `touched` flag keeps it from fighting a reader who has panned or zoomed, and `fit` clears it.
  - **EVERY screen reads the same scales, and a raw literal is the regression.** `styles.css` defines spacing `--s0..--s6` (2/4/8/12/16/24/32) and type `--t-nano..--t-display` (9/10/11/12/13/14/16/20/26/44); there are zero raw `font-size: <n>px` declarations left in the sheet, and gap/padding/margin literals survive only where the number is component GEOMETRY (a 92px record button, a 38px switch), never rhythm. The half-pixels the type scale replaced were the tell that no scale existed — **9.5, 10.5, 11.5 and 12.5px were all in use**, four sizes nobody can distinguish doing the work of two, and the Library measured 46/20/18/12/12 down its length with every number chosen locally. Add a step only when a real need has no home; snapping to the nearest is the default.
  - **Audit the sheet for UNDEFINED tokens, because they fail silently.** `--panel-2` was referenced by `.gbtn` and `.gnode` and defined nowhere, so both `background` declarations were invalid at computed-value time and fell back to `transparent` — Flows node cards had no surface, on a canvas of the same colour. Nothing errors and nothing logs. Diff `var(--x)` against `^\s*--x:` after touching the sheet; `--frame-ar` (set inline by `DetailView`, and carrying a fallback) and `--tone` (set on the one-line `[data-tone]` rules) are the only legitimate absences.
- **`styles.css` is ONE global sheet with no modules or scoping, so a class name is a repo-wide identifier.** The node drawer is `.drawer` because `.sheet` was already SearchScreen's contact-sheet grid (`display: grid; repeat(auto-fill, minmax(232px, 1fr))`) — and a base rule that does not restate `display` silently inherits the colliding one's. The drawer's header and body became side-by-side grid items, its three body columns collapsed into one ~250px track, and every predicate wrapped to one character per line. It typechecks, it builds, and only looking at it shows anything is wrong. Grep the file for a base class before minting one — `.routes` was minted in the same change that deleted `.route`.
  - **`TraceNode.visual.frameBlobId` holds a FRAME id, not a blob id** (`lift.ts` stores `snap.frameId`), so `deskrag://frame/<blobId>` cannot serve it directly — `DeskRagService.frameBlobId()` resolves it. The misleading name is still in the library.
  - **Node labels legitimately collide** (two Chrome states both label "Google Chrome"), so the id chip is what distinguishes them — and chips must widen with a slice of the session ULID wherever a suffix repeats, which a second recording produces immediately.
  - **The graph flows DOWNWARD and its layout is pure** (`graph-layout.ts`, in the ROOT suite like `graph-view.ts`). Rank is the row, so the graph grows along the axis a window has to spare. Within a rank, order by the mean x of already-placed parents — ties break on array index, and that tiebreak is load-bearing: a layout that reordered on equal barycenters would twitch on any re-render. **A SELF-LOOP needs its own path:** a revisited state collapses into a loop whose endpoints coincide exactly, so an out-and-back cubic degenerates into a flat horizontal stub that reads as a broken wire — measured on the real graph, fixed by giving it vertical extent.
  - **There are TWO distinct reasons a node cannot be told apart and the UI must not confuse them:** an `app`-only identity is satisfied by every state in that application, while a ZERO-predicate node is vacuously a subset of every observation. Measured: the real graph's entry node has no predicates and was being told its identity was "only `app`".
  - **Pure renderer modules must be `.ts`, never `.tsx`, to be root-testable.** The root `tsconfig.json` sets no `jsx`, so a root test that reaches into a `.tsx` even for a *type* breaks `npm run typecheck`.
  - **The deep link carries LANE seconds, and `TrackRail.seek` is the one converter.** `Flows|Search → Library → SessionPlayer → TrackRail`: `atSec` is a `t_mono` offset all the way down, because the encoded video runs ~1% short of the span it covers and dividing one clock by the other's total is the bug to watch for. The seek waits on `mediaSec > 0` rather than sleeping — a fragmented MP4 reports `Infinity` until the provider adopts a real duration. The Library clears `openAt` once consumed, or picking another recording re-seeks.
    - **TWO producers, ONE minter.** Search joined Flows on 2026-08-07 (`FrameHitDTO.sessionId` + `offsetSec`, a jump on every result card and in `DetailView`), and `App.tsx`'s `openRecording` is the only place an `OpenAt` is built. Before it, retrieval found a moment and then stranded the reader on it: `SearchScreen` was the one screen mounted with NO props, and the hit did not even carry a `sessionId`.
    - **`laneSec`/`laneOriginOf` (`session-tracks.ts`) are the one definition of what a moment IS**, and the reason they exist is that a second producer found the first one wrong. Lane offset 0 is `video.tMonoStart`, never `t_mono` zero — capture runs while ffmpeg is still spawning, **measured at 450–1800ms of pre-roll across four real recordings** — and `graph-view.ts` minted `atSec` as raw `tMono / 1000`, so every Flows jump landed that much early. Four callers read the rule now (the rail's origin, the keyframe markers, a search hit, the Flows sources). It clamps at 0: the rail can DECLARE a pre-roll stretch (`preRollSec`, the hatched edge), a seek target cannot.
    - **`OpenAt` carries a NONCE, because the same moment twice is two jumps.** React bails on identical state and `TrackRail`'s `seekDone` guard fires once per request — keyed on the seconds, the second identical jump was a dead click, which Search hits immediately since the screen unmounts on navigation and returning means re-running the query. Keyed on the nonce it works: verified in the running app, playhead parked at 0.5s, same hit clicked again, back to 20.109378.
    - **The landing is correct against `t_mono`, and that was measured, not argued.** A search hit stamped `t_mono` 21909.708 seeks to media 20.109378 (= `offsetSec`), and the recorder's own millisecond clock IN that video frame reads **21.910** — agreement to the millisecond, `20.109 + 1.800 = 21.909`. The proportional alternative (`(sec/totalSec)*mediaSec` = 18.938) reads 20.310 there, ~16 frames early. So `videoSec` still being the seeded span at seek time makes the rescale a no-op AND lands on the right frame, agreeing with the chapter cues and `stepKeyframe`, which both use `offsetSec` as media time directly. **Do not "fix" that guard without re-taking this measurement** — extracted with `ffmpeg -ss <t> -i <blob>`, because Playwright screenshots the video's FIRST frame no matter where it is seeked.
    - **The keyframe-lags-its-own-`t_mono` bug was FIXED on 2026-08-08**, in two passes — see the `FfmpegScreenProducer` paragraph above. It was never the MJPEG branch: gray and MJPEG arrive within 1ms of each other, and the cause was arrival-time stamping carrying the whole capture latency. The first pass stamped from PTS and fixed frame↔video exactly, but put frames on the MEDIA clock while events stayed on `t_mono` — visible on the rail as an APPS lane ~0.9s right of the picture. The second pass added the device-clock bridge, so both are on `t_mono`. **Recordings made before that keep the skew and are NOT comparable**; `session_clock`'s absence is what marks them, and the rail says so.
- **The MCP endpoint (`app/src/main/mcp/`) is the only way anything outside the app reads the index, and it is READ-ONLY BY CONSTRUCTION.** Six tools — `search_experience`, `get_moment` (the keyframe as an MCP image block), `list_recordings`, `get_recording_outline`, `list_flows`, `get_flow` — hosted by the app over stateless Streamable HTTP on `127.0.0.1:41777`. It reuses `DeskRagService` verbatim, because that is the single owner of the store and the providers: a standalone stdio binary would be a SECOND owner, duplicating `buildProviders` wholesale and opening SQLite and LanceDB behind the app's back. The cost, stated: the app must be running.
  - **`test/mcp.readonly.test.ts` is the whole safety story**, the same principle as `test/replay.barrel.test.ts`. No file under `mcp/` may import `replay/`, name `ax-exec`, spawn, or call `startRecording`/`removeSession`/`reindex*`. It reads CODE — comments are stripped, and the stripper is itself tested, because it first fired on a comment *discussing* `ax-exec` and a guard that trips on the discussion is one the next person deletes. **`close` is deliberately not guarded by name** (it is the HTTP server's and the transport's method too); closing the STORE is prevented by TYPE, since the reader holds a `ServiceReads` port that does not declare it.
  - **THE HOST CHECK IS WHAT CLOSES DNS REBINDING; the Origin check cannot.** Once `evil.example` has rebound to 127.0.0.1 the browser considers the target same-origin and sends **no Origin header at all** — only `Host: evil.example` gives it away. Both run, Host first, ahead of the method and the path so a rebound page cannot even learn the route. Verified against the live socket: cross-origin 403, rebound Host 403, GET 405. Note `fetch` **cannot** forge Host (a forbidden header), so the test uses node's raw client — a restriction a real browser does not have.
  - **There is deliberately NO token**, a decision taken with the risk on the table: any local process can read the whole index, and typed text is not redacted (`buildDigest` folds it in on purpose). The gate is instead the visible activity log in Settings. Both facts are stated in the pane, not just in the spec.
  - **A bind failure is reported, never retried onto another port** — the user has already pasted a fixed URL into an agent's config, so a server that quietly moved presents as broken. `enabled` and `listening` are separate fields for this reason.
  - **The low-level `Server` is used, not `McpServer`**: `registerTool` types `inputSchema` as Zod, which would put Zod inside `tools.ts` — pure, SDK-free and root-tested so the tool surface can be argued about offline.
  - **An empty search result is the shape of three different states.** `indexedUnderDifferentProvider` and `segmentsMatchedButNoFrames` are rendered as prose; a bare empty list makes an agent report "you never did this" when the truth is a namespace mismatch.
  - **Confirmed on a real store (2026-08-13), in the DEFAULT configuration (`imageProvider: "none"`)**: 13 recordings, search returning real hits at score 1.000, a full `SESSION → PROCESS → TASK → ACTION` outline, six recorded routes, and a 275 kB keyframe over the wire. `npm run probe:mcp` re-runs all of it.
- **Lifecycle:** window close hides to a menu-bar tray and recording keeps running; only Quit closes the store.

## Non-obvious invariants (verified the hard way — don't regress)
- **The Swift sidecars emit AX roles WITHOUT the `AX` prefix** (`ax-dump.swift`: `rawRole.dropFirst(2)`), so real data carries `Button`, `Window`, `TextField`. Every consumer of `UIElement.role` must normalize — `axFilter` does (`r.replace(/^AX/i, "").toLowerCase()`) and `trace/predicates.ts` does (`canonicalRole`). Matching prefixed literals compiles, passes hand-written fixtures, and silently produces **zero predicates from every real recording**: that shipped once, and it collapsed the whole graph to one node with no waits and no slots. There is still **no checked-in fixture captured from the real sidecar**, which is exactly why it survived; adding one is an open derived requirement.
- **`ax-exec`'s attribute readers must match `ax-dump`'s exactly, and the empty-string rule is the one that bites.** Both treat an EMPTY attribute as absent (`if let s = value as? String, !s.isEmpty`), so `AXTitle: ""` falls through to `AXDescription`. `ax-exec` originally returned `value as? String` verbatim — a one-line difference that made it disagree with `ax-dump` on exactly one of 48 elements (the font-size stepper, whose AXTitle is empty), and that single label was enough to stop any node from verifying at replay. Two binaries reading one tree is a standing drift hazard: when changing either reader, diff both against a live app index-by-index, not just by element count.
- **A real AX dump exceeds 64KB, so sidecar stdout arrives in several chunks and a chunk boundary lands mid-JSON.** Buffer until a newline before parsing (`sidecar.ts` does). Splitting each chunk independently yields truncated "lines" that parse-error only on large trees — it works fine against every small test fixture.
- **Adding a TABLE is the sanctioned schema move, and it genuinely works on an existing install.** `CREATE TABLE IF NOT EXISTS` runs on every open, so a new table appears on a database that predates it while an existing table's *shape* still can never change. `transcript_clip` was added this way (after `ax_snapshot`, `ax_snapshot_boundary`, `trace_node_source`, `segment_app_caption`), and it was **verified rather than assumed**: a copy of a pre-change `app.db` was opened with the new code, gained the table, and lost nothing. So no data-dir reset is needed for a table addition — only a change that alters what an existing column *means* needs one (see the `phash` note above).
- **`grep` silently SKIPS `src/store/store.ts` — use `grep -a`.** It contains two deliberate NUL bytes, as the delimiter in composite map keys (`` `${namespace}\0${id}` ``, safe because neither part can contain one). `file` therefore reports it as `data`, and grep treats a binary file as a match-or-nothing: it prints *no* matching lines and *no* error, so a search over `src/` reads as "this symbol doesn't exist" for the one file where most of them live. `rg` is no better — it prints `binary file matches` and no lines. Both need the text flag: `grep -a` / `rg -a`. Verified on both.
- **`better-sqlite3` `safeIntegers` does NOT reach UDF arguments** (only column reads become BigInt). So the 64-bit pHash Hamming (Tier 0) runs in JS, not a SQL UDF, and `hydrateFrame` must `Number()`-coerce the small INTEGER columns that come back as BigInt under safeIntegers.
- **LanceDB `.where()` PRE-filters by default** in the JS SDK — that's what makes Tier-2/3 scoping exact. `array_has_any(segment_ids, [...])` is the segment-scope predicate.
- **Pinned deps for a reason:** `apache-arrow` is pinned to `18.1.0` (LanceDB peer-caps it `<=18.1.0`); `sharp` is `^0.35.3` (0.34.x had libvips CVEs). Don't bump these blind.
- **`@vidstack/react` (the Library player) must be installed as `^1.15.6` — npm's `latest` dist-tag is stale.** `latest` still points at `0.6.15`, an abandoned line that peers `react ^18` only and has a different API; the current release ships under the `next` tag. A bare `npm i @vidstack/react` silently installs the wrong major. It is a renderer-only devDependency (electron-vite bundles it), pure JS with no native module, so it needs no electron-rebuild and no root-package mirror. It is also local by construction: its theme CSS contains no `@import`/`url()`, its deps are `@floating-ui/dom` + `media-captions`, its icons are inline SVG, and its only CDN path — the hls.js/dash.js loader — is unreachable for an MP4 source and blocked by the renderer CSP (`script-src 'self'`) regardless. Keep the source typed `video/mp4` explicitly: `deskrag://media/<blobId>` has no file extension for Vidstack to infer from.
- **`onnxruntime-node` is pinned to `1.27.0` with a known, accepted advisory.** It depends on `adm-zip <0.6.0` ([GHSA-xcpc-8h2w-3j85](https://github.com/advisories/GHSA-xcpc-8h2w-3j85), CVSS 7.5). Accepted deliberately: `adm-zip` appears only in `script/install-utils.js` (unpacking a NuGet package at install time), never in the runtime `dist/`, so nothing the app executes reaches it; the impact is availability-only (a crafted ZIP forces a 4GB allocation), not code execution; and npm's only "fix" is downgrading to `1.21.1`, a semver-major step backwards. `npm audit` will keep reporting it — that is expected, not a regression. Do NOT use `@huggingface/transformers` as a tokenizer source: it depends on `sharp ^0.34.5`, which conflicts with the pin above and would nest a CVE-era libvips copy. Use `@huggingface/tokenizers` (pure JS/TS, zero deps) instead.
- **`OnnxImageEmbedding` embeds ONE image per forward pass, on purpose.** The int8 export returns cosine 0.992 — not 1.0 — for the same image at batch 1 vs batch 2, because onnxruntime selects a different kernel per batch dimension (the fp32 export is bit-exact, so it is quantization, not an indexing bug). That would be harmless if both sides batched alike, but they never do: `FrameRepresenter`/`RegionRepresenter` hand every pending image to one call while Tier 2/3 always embed a query as `[image]`. Batching would put stored and query vectors on different kernel paths permanently. Costs ~16% throughput; do not "optimize" it away. Pooling is the **CLS token** (`last_hidden_state[:, 0]`), never a mean — mean-pooling yields plausible vectors that quietly retrieve worse.
- **Coordinate spaces:** AX bboxes and mouse hotspots are both global **screen** coordinates (top-left origin); the stored JPEG keyframe may be downscaled, so `SharpRegionCropper` maps the bbox from frame space → image space via `sharp.metadata()`.
- **AX is captured live at capture time and stored** (`frame_ax` table), then read back at represent time via `StoredAxProvider` — never queried live during represent (the UI has moved on).
- **Electron's Node ABI ≠ system Node's — solved by two isolated installs, not by switching.** `app/` is deliberately NOT an npm workspace member: it has its own `app/node_modules` with its own `better-sqlite3`, rebuilt for Electron by `app`'s `postinstall` (`electron-rebuild -f -w better-sqlite3`). The library's root copy stays Node-ABI for `npm test`; the two never share a binary, so neither rebuild touches the other. `better-sqlite3` is the only ABI-fragile module (raw Node addon); `sharp`, `@lancedb/lancedb`, `uiohook-napi`, and `active-win` are N-API/prebuilt and are never rebuilt. The runtime resolves the app's copy first because `app/out/main/index.js` externalizes `better-sqlite3` as a bare specifier and `app/` is nested inside the repo, so Node's upward walk hits `app/node_modules` before root. **Consequence:** native version pins now live in both `package.json`s (`better-sqlite3`, `sharp`, `@lancedb/lancedb` + the platform optionals) — keep them in sync.
- **`searchSegments` throws on an unregistered namespace**, so a `Retriever` must only be given `TextViewSearcher`s whose namespace appears in `store.listVectorSpaces()` — caption/transcript spaces don't exist until something has been indexed with those providers. `BehaviorViewSearcher` is always safe (it returns null without a behavior vector). See `DeskRagService.buildRetriever`.
- **The app imports `dist/`, not `src/`** — after changing library code, `npm run build` before launching (`npm run app:dev` does both). Library types changing means the app's typecheck can break without any file in `app/` changing.
- **`scripts/brand/emit-icons.ts` is macOS-only** — it shells out to `iconutil` to build the `.icns`. The rasterised PNG/ICNS/ICO binaries it and `emit-icons` produce are deliberately NOT drift-guarded byte-for-byte (unlike the SVG/Lottie emitters): libvips/librsvg output varies by version, so the test suite only checks the committed tray PNG isn't stale (alpha at a couple of geometry-derived pixels), not that it's byte-identical to a fresh render.

## Validate against a real recording before trusting a measurement
Three of this repo's worst bugs were invisible to `npm test` and obvious within minutes of driving a real session through the pipeline: the AX role prefix (above), a stale sidecar, and text search returning nothing at all on the default provider configuration.

**And test the DEFAULT configuration, not the fully-configured one.** The zero-results bug survived because every retrieval test constructed the `Retriever` with an image embedder, while the shipped default is `imageProvider: "none"`. A suite that only exercises the richest setup cannot see the setup most users have.
 Synthetic fixtures agree with whatever the code assumes. **Before designing on top of captured data, record a real session and read what actually landed in the store** — and treat any number derived from one application as provisional, because the anchor ladder was falsified twice, each time by recording in one more app.

**And read the BYTES, not just the row counts.** The silent-microphone default above produced a perfectly healthy-looking store — two `mic` blobs, exact byte counts, contiguous `t_mono` spans, no error from ffmpeg or anywhere else — and every sample in them was zero. Twelve seconds of recording found it; no assertion over the schema could have. When a signal is audio or pixels, measure the content (`ffmpeg -af volumedetect`, `ffprobe`) before believing it was captured.

## Build order when extending
Follow the dependency direction: `embed/` + `store/` first (prove the seam with the crash-recovery and scoped-ANN tests), then `timeline/` → `capture/` → `segment/` → `represent/` → `retrieve/`. New embeddable views register a `vector_space`, write text/raw first then the vector, and slot into reconciliation and a Tier-1 `ViewSearcher`. The app comes last: a new capability surfaces as a `deskrag` barrel export → an indexing stage or searcher in `DeskRagService` → a `Capabilities` flag + DTO field in `shared/types.ts` → UI.
