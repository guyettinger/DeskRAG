# Trace IR and the executor

Recorded behavior as a manipulable graph, and the only code in the repo that acts on the world.

> Moved out of `CLAUDE.md` on 2026-08-15, verbatim. Every number here is a measurement
> taken from a real recording or a real run — not an estimate. Re-measure before changing one.

A `Trace` is one recorded session lifted into a linear chain; a `Graph` accretes from merging traces at equivalent states. Nodes are verified states (a predicate set extracted from the AX tree, filtered to stable attributes), edges are action sequences. **Variation comes from recording a task twice, not from a model inventing it** — two recordings differing only in typed text merge into one edge with two slot samples, which is how slots are discovered rather than declared. A revisited state collapses into a loop.

- **Targets are layered anchors** (`ax → visual → point`), recorded independently at lift time and **never derived from one another** at replay time. Anchors resolve against the AX tree captured *at that moment*, the same rule `StoredAxProvider` enforces at represent time.
- **Paths are normalized to a unit box between their endpoints**, so retargeting is the same projection as verbatim replay — one code path, not two. `Path.curve` is a *chain*: a single cubic misses a half-sine arc by ~3% of its chord. Spans split at the **index** midpoint, never at peak residual or the arc-length midpoint — both make the fit flip under a pure translation of the input, because on a symmetric gesture the two candidate samples are exactly equidistant and floating-point noise alone decides.
- **Predicates are tagged `achievable` or `assertable`.** Achievable ones have a repair path (pathfind to a node where they hold), assertable ones can only gate. Setup is therefore not a separate phase: it is the graph, and mid-replay recovery uses the same mechanism. **`reach` is DENORMALIZED into every stored predicate**, so editing `REACH_BY_KIND` changes nothing about a graph already on disk — it needs a rebuild. Measured the confusing way: `url` was flipped to `achievable`, the code and tests all agreed, and a live plan was still blocked by `url/assertable` read straight out of `trace_node`.
- **Identity is predicate-primary; ambiguity declines to merge.** A redundant node is visible and fixable; a wrong merge is silent corruption.
- **A node's identity is WHAT THE TASK DOES NEXT, not what is on screen** (`trace/identity-set.ts`). `extractPredicates` still decides what a live tree *yields* — `STABLE_ROLES`, `isVolatileLabel` and the 64 cap are unchanged — but a node keeps only: `app`; the elements its **outgoing** edges' anchors target; `ax_focused` when an outgoing edge types; the **incoming** edge's `wait` predicates; and a URL prefix. Everything else is dropped, so no page-vs-chrome heuristic is needed — content the recording never touched is excluded by construction. **Measured on a rebuilt real graph: max predicates per node 34 → 4, mean 2.0, and zero nodes carrying page furniture** (the Chrome nodes that held 18 GitHub PR predicates, which made a live armed run fail boundary verification, now hold two). Both halves of the merge contract hold on real recordings: two recordings of one PR page collapse into a single node (`observations = 2`), while the issues page stays separate on its `url`.
  - **This exists because ONE set was doing TWO opposed jobs.** Merging wants more predicates (discrimination); locating wants fewer (robustness). `DEFAULT_MAX_AX_PREDICATES` went 32 → 64 to stop two GitHub pages merging wrongly, and that same move is what made nodes unlocatable. No cap satisfies both.
  - **Waits come from the INCOMING edge**, filtered by what actually held in the observation. A `wait until app(X)` asserts where an edge *arrives*; reading it from the outgoing edge is the same off-by-one that made boundary snapshots describe the previous application. `newlyTruePredicate` is ranked (`app` → `url` → `ax_focused` → rest) rather than first-wins, or a browser edge's wait would be page furniture and would smuggle it back in.
  - **Lift is three-phase by necessity:** full observed predicates → edges → narrow. `buildNode` runs before any edge exists *and* waits are derived from the full sets, so identity can only be computed last.
- **`ax_exists` is keyed by `identifier` where one exists, else `label`** — one predicate per element. `LAYER_CEILING` ranks `AXIdentifier` at 1.0 against a label's 0.8, yet identity was built from labels alone, so the strongest descriptor never reached it; the failing run's own target (`TextArea` `#First Text View`, no label) contributed nothing.
- **`url` is a predicate** (`trace/url.ts`). For a browser the real application is the SITE: `app=Google Chrome` is too coarse and full page content far too specific. The prefix drops id-like path segments and caps at 3, so two PRs in a repo merge while two repos do not. **`achievable`**, not assertable: `Reach` asks whether some EDGE establishes the predicate, and navigating does. Written `assertable` first, which made every browser node a permanently unreachable goal — `buildPlan` turns an unmet assertable predicate on a remainder node into an unoverridable blocker. Wrong-page replay is still prevented, by verification and locating, which both gate on it. Sourced from `AXURL` on the focused window's `WebArea`, read **during** the walk (Chromium puts it at depth 8–11, so a shallow separate search silently finds nothing) and carried as a `url_change` **event**, because `ax_snapshot` has no column and there is no migration mechanism.
- **A node whose identity is only `app` VERIFIES but never LOCATES** (`isLocatable`). `app` is shared by every node in an application, so it cannot answer "which state is this?" while answering "did I arrive?" perfectly well. **Consequence, measured: without a URL only 3 of 8 nodes were locatable; with one, 9 of 13 are.** Web scope is therefore not only about disambiguation — it is what makes a browser node addressable at all, since a second predicate is what lifts it off the floor. Where nodes remain bare `app` they also over-merge (`observations = 6` on one), which is visible and inert precisely because those nodes cannot be located. `run.ts`'s preference for the `expected` node is what carries a run through them.
- **A boundary node's AX tree must be fetched by its BOUNDARY, not by timing.** `BoundaryAxTrigger` waits out a settle delay before walking, so the snapshot's own `t_mono` is always ~250ms LATER than the boundary it describes — measured at 250–252ms across every stamp. A "latest at-or-before" lookup therefore returns the *previous* state's tree, which paired each node's incoming `app`/`window` predicates with the outgoing app's UI. It measured **54% of nodes incoherent** before the fix and 0% after. `getAxForBoundary` matches exactly via `ax_snapshot_boundary`; `getAxAt` remains the fallback for sessions recorded before stamping existed, and **those graphs cannot be repaired by re-lifting** — the stamp was never captured.
- **Waits come from two paths.** A gap ≥ `dwellGapMs` is cut by `computeBoundaries` into a boundary, so it falls *between* spans and never appears as an intra-span idle gesture — and that is the canonical wait. Only smaller gaps arrive as gestures. A wait whose predicate was already true is dropped with a warning, never emitted as a no-op that looks like a check.
- **`trace/` is a leaf** — pure TS, in the barrel, and it never imports `store/`, `represent/` or `retrieve/`. External data arrives via injected callbacks (`VisualMatcher`, `LiftInput.axAt`) and the minimal local `TraceEvent`/`AnchorRegion` shapes (the same pattern `segment/types.ts` uses for `SegEvent`). Graph *persistence* lives in `store/` (the `trace_*` tables, keyed `(graph_id, id)` because node ids are graph-scoped), which imports the `Graph` type — one direction only. No vector space is registered; visual corroboration reuses existing region/frame vectors by id, so graph writes have no SQLite→Lance ordering hazard.
- **Key events without a resolved `char` emit no text gesture, by design.** `UiohookInputProducer` writes `{ keycode, modifiers }` and `resolveKeys` resolves the character from the session's own `keymap_change` event; a session recorded with no keymap therefore loses ALL typed content silently, which is why the Trace stage reports it in its progress label. A static keycode table would fabricate typed content and hide the gap.
- **`parseInterventionResponse` is a security boundary.** An unknown edge id, an undeclared slot, or synthesis under `allow: "select"` all become `{ abort }` — a model must not widen its own permissions by malforming a reply.

See `docs/superpowers/specs/2026-07-30-experience-trace-ir-design.md`. Capture enrichment shipped (`…-replay-fidelity-capture-design.md`); the executor is below. Only subsystem #4, AI-in-the-loop, is still unbuilt — its wire contract is fixed in the IR spec, its runtime is not.

## The executor (`src/replay/`)


A `Plan` is produced by resolving a graph against the live AX tree; arming it replays those actions with CGEvents. `replay/` is a leaf like `trace/`, and it spawns a subprocess but loads no native module, so it **is** in the barrel.

- **`execute.ts` depends only on an injected `Actuator`, and `test/replay.barrel.test.ts` asserts that no file in `replay/` except `sidecar.ts` mentions `spawn`/`child_process`.** That guard is the whole safety story: the suite is *structurally* incapable of posting a real event. Never widen it by reaching for a process from a resolver, a planner, or a verifier.
- **`native/ax-exec` is a SEPARATE binary from `ax-dump`, on purpose.** `ax-dump` is read-only and three of its modes are deliberately permission-free (`--displays`, `--keymap`, `--clock`); folding actuation in would mean every AX read is performed by something that can also click. `ax-exec` gates on `AXIsProcessTrusted()` *and* refuses to start without `--plan <id>`, so a bare invocation is inert. `npm run build:ax` builds both.
- **The sidecar is long-lived with a JSON-line protocol**, because AX element handles must stay warm between `locate` and the action using them — re-walking the tree in between is a staleness window in which the UI moves.
- **The anchor ladder's middle is ORDERED BY TRUST, not fixed.** `identifier` is always first and `point` always last, but `label` vs `path` is decided per anchor by `pathCeiling(depth)`, which decays a path's trust from 0.95 and crosses below a label's 0.8 just past depth 5. This is not over-engineering and must not be "simplified" back to a constant: two *fixed* orders were each falsified by recording in one more application. Measured path depths are AppKit 4.0, SwiftUI 7.4, Chromium 11.4 (max 17) — and the apps disagree about label-vs-path *because* their depths differ. SwiftUI also carries **0% labels**, AppKit 67% identifiers against Chromium's 9%; availability is a property of the app's AX implementation, never a ranking criterion.
- **Verification is a SUBSET check, deliberately unlike node identity.** `samePredicateSet` is exact because *merging* needs it; verification asks only "does every predicate this node claims still hold", so extra observed predicates are not violations. Exact equality here would fail on any screen that gained anything since recording.
- **Dry-run is the default and arming is one gate.** `blockers` (unmet `assertable` predicates) can never be overridden — no UI action produces them. Brittleness (an edge whose targets are majority point-only) can be, explicitly.
- **A plan STOPS where resolution stops working, and the rest is disclosed unresolved.** `buildPlan` cuts at the first anchor that carries AX descriptors yet reaches no AX rung — the executor *measuring* that it is describing a state which does not exist yet. A point-only anchor never cuts: it is already at its permanent best. That edge and every later one become `remainder` — action kinds, recorded descriptors, recorded points, explicitly not targets — and the cut is at an EDGE boundary, never mid-edge, because a node boundary is the only place the world can be re-observed. `executeRun` (`replay/run.ts`) then loops observe → locate → plan → **arm** → execute, with `arm` INJECTED so `replay/` still never decides to act. The dry-run promise is unchanged in substance — *nothing is posted from a plan you have not reviewed at exact resolution* — and segmentation costs approvals rather than safety. Measured on a real cross-app graph: 2 segments, cut exactly at the app boundary, and 0 anchors falsely resolving in the wrong application across 9 foreign trials.
- **The recorded app switch is SUPERSEDED by the repair, and the repair goes at the edge's END.** On an edge whose destination app differs, the switch is the edge's **final** action when it is spatial and carries no `ax` layer — 4 of 4 measured, and structural rather than lucky: `computeBoundaries` cuts at the focus change, so the switching action is by construction last, and the switch target sits outside the focused window's tree by definition (which is *why* the Dock click is point-only). Every `wait { until: app(X) }` is dropped too, since `runRepair` polls that predicate itself. Both become visible `SupersededStep`s, never silent omissions. The repair belongs at the END because the `app` predicate is on the DESTINATION node while the edge's own actions run in the SOURCE app — placing it first posts one app's clicks and keystrokes into another, which is what the shipped code did. Suppressing the switch is also what makes cross-app edges armable at all: their AX rate goes 0%/50% → 100%, and below-floor edges 2/4 → 0/4.
- **`locateNode` uses the SUBSET rule, not `trace/identity.ts`'s `matchNode`.** Merging needs exact set equality — a differing set is a different state — but locating asks "which recorded state is still true here?", and a live screen that gained anything would never match exactly. Most predicates wins (subset matching is monotone, so a node carrying only `app` is satisfied by every observation in that app), a tie declines, and a **zero-predicate node is never a candidate** — an empty set is vacuously a subset of every observation, so it would verify against any desktop at all.
- **Execution verifies at every node boundary**, using the same subset rule, and a violation aborts naming the predicate. The spec promised this from the start and the code did not do it until progressive resolution needed it, because the next segment re-plans from wherever execution actually left the world.
- **An unmet `app` predicate is repaired by ACTIVATING the app, and the repair is a visible plan step.** `app` is tagged `achievable`, so the IR promises a repair path. The graph does contain the recorded switch — as a point-only Dock click — but replaying a coordinate on a surface whose contents move fails silently, because a click always "succeeds". **Planning may call `runningApps()` but never `activate()`**: activating to discover whether an app is running would change the world the plan describes, and `test/replay.barrel.test.ts` asserts `plan.ts` never calls it. Not running is a blocker unless the caller passes `allowLaunch`, and the decision is recorded on `RepairStep.launch` so the review shows whether a launch can happen. Activation is confirmed by polling the predicate, never by sleeping. Launch resolves by **bundle identifier only** — an `app` predicate carries a `localizedName`, so launching usually reports `not-running`; guessing an app from a display name could launch the wrong one.
- **`type` has no fallback layout.** No keymap, or text the layout cannot produce, is a *blocker* — never a US-QWERTY guess. Same rule, opposite direction, as `resolveKeys` at lift time; one keymap serves both.
- **Clicks are CGEvent, never `AXPress`.** `AXPress` is a different action (no hover, no mouse-down, different event stream), so it would silently diverge from what was recorded.

See `docs/superpowers/specs/2026-07-31-executor-design.md` and `…-2026-08-01-progressive-anchor-resolution-design.md`. **The loop first ran end to end with a real CGEvent on 2026-07-31** — one click, one app, target already frontmost. **On 2026-08-01 a cross-app plan was armed from the app's then-Replay screen and posted real events**: a `3× click` resolved at `identifier@1.00`, a `cmd+a` chord, a `type`, and an activation repair that brought Chrome forward — the first live exercise of chords, typing, the repair, supersession, and a cut plan. It confirmed two orderings that were previously only argued: the repair must be the edge's **last** step (steps 2–5 posted into TextEdit, Chrome was activated at step 8), and suppressing the recorded switch is what makes the edge armable at all (3 of 8 steps superseded, all of them the switch). That run **stopped after segment 1**, failing boundary verification on the 18 GitHub predicates — which is what task-derived identity above exists to fix. **On 2026-08-02, after that fix, a multi-step armed run posted nine steps into a real desktop and was verified on screen**: the reviewer hid, TextEdit came forward, a `CheckBox "bold"` click at `path@0.88` toggled bold, a `TextArea` click at `identifier@1.00` focused it, a `type` put real characters in the document, and an activation repair brought another app forward. That is the first live confirmation of **typing** end to end — keymap captured at record, resolved at lift, replayed through `strokesFor`, characters on screen — and of the focus handoff under a **multi-step** sequence rather than one click.

It then **correctly refused to continue**: boundary verification named `ax_exists(label="Stop recording")`, a button that exists only *while recording*, so the state genuinely did not hold. **DeskRAG is deliberately NOT special-cased out of recordings** — excluding one app by name would be exactly the app-specific heuristic this design exists to avoid, and that predicate is correct identity, unverifiable outside recording mode for the same reason a node recorded with a modal open is unverifiable with it closed. Sessions start and end in the app, so its nodes are hubs paths route through; the remedy is recording a route that does not detour through it, not code. **Continuation past a cut still has never run against a real desktop** (it aborts before segment 2); it runs in the suite via `test/run.expected.test.ts`. Drags remain fake-only. Treat every other figure as a capture-time or dry-run measurement.

**`scripts/replay-probe.mjs` is the read-only harness for all of this.** It wraps the `Actuator` in a proxy that throws on `activate`/`moveTo`/`click`/`dragPath`/`scroll`/`key`, so it is structurally incapable of posting an event — the same principle as the barrel guard, and what makes it safe against a live desktop. Modes: `--offline` (graph only, no permissions), `--sweep` (does any anchor falsely resolve in the wrong app?), `--diagnose-frontmost` (long-lived vs fresh sidecar), `--wait-for <app>` (poll until an app is frontmost, since running the probe necessarily focuses a terminal).

**AS OF 2026-08-06 THE EXECUTOR HAS NO UI AND IS REACHED ONLY FROM THE SUITE AND THIS PROBE.** Everything above still describes `src/replay/` accurately and every `test/replay.*` case is green; what was removed is the app's plan-review surface, which never became reliable — see `docs/superpowers/specs/2026-08-06-flows-graph-exploration-design.md`. The app's screen is now **Flows**, a reader over the same graph. Consequence worth stating plainly: **DeskRAGApp no longer spawns `ax-exec` at any point**, so the live measurements above cannot be reproduced from the app. Re-wiring it is a deliberate act, not a refactor.
